# LogicWrite 프로젝트 기획서

> **간단 기획 요약 · 현행화 2026-11-10 (PR #15 기준)**
>
> 목표와 기대 효과를 요약한다. Core는 제한된 실행 프로토타입이며 정식 완성·품질 향상 입증은 아니다. 상세 구현 현황은 [현재 실행 인터페이스](data-model-and-interfaces.md#current-runtime-interfaces), 확장 계획은 [프로젝트·RAG/LangGraph 기획서](logicwrite-project-proposal.md)를 참조한다.

## 1. 프로젝트 개요

- **이름:** LogicWrite — Logical Writing for Agents
- **한 줄 소개:** AI가 작성한 글의 정보를 독자와 목적에 맞게 선별·구성·표현하고, 중요한 내용의 누락과 논리적 문제를 검증하는 글쓰기 품질 관리 시스템.
- **첫 적용 대상:** 한국어 기술 문서(README, PR 설명, 설치·사용 가이드, 설계서, 업무 보고서)
- **주요 사용자:** AI를 활용해 기술 문서를 작성하는 개발자·팀과 에이전트 개발자

## 2. 문제와 필요성

AI가 생성한 글은 문법적으로 자연스러워도 독자의 목적에 맞지 않는 구현 이력, 중복 설명, 부적절한 정보 배치, 과장된 주장, 빠진 조건·근거 때문에 이해와 검토를 어렵게 만들 수 있다. 글을 짧게 만드는 것만으로는 해결되지 않는다. 특히 에이전트가 **문서의 목적부터 잘못 판단**하면 이후의 윤문도 잘못된 구조를 강화한다.

## 3. 목표

독자가 필요한 정보를 정확한 범위와 순서로 이해·판단·실행할 수 있는 문서를 만들도록 돕는다. 작성 과정에서 주장·수치·조건·근거·출처를 추적해, 재배치와 표현 수정이 핵심 의미를 바꾸지 않도록 검증한다. 결과에는 판단 근거와 해결되지 않은 문제를 남긴다.

## 4. 목표 기능과 작동 방식

| 구성 | 역할 |
| --- | --- |
| **Writing Contract** | 사용자 의도, 독자, 목적, 필수 정보, 제약을 정한다. 현재 문서에서 추론한 목적과 충돌하면 근거를 확인한다. |
| **① 정보 추출·분석** | 글을 정보 단위로 나누고 주장·수치·조건·출처의 관계, 중요도와 적합성을 판단한다. |
| **② 정보 재배치·재구성** | 정보별 문서·섹션·순서를 결정하고 중복을 통합한다. 다른 문서로 옮길 때는 목적지의 실제 내용을 확인한다. |
| **③ 표현 수정** | 필요한 정보를 보존하면서 문장, 용어, 문체, 분량을 다듬는다. |
| **Validation Gate** | 필수 검사 목록과 실행 결과를 대조하고 원문·최종 결과의 정보 보존 및 논리적 문제를 검증한다. |
| **Revision Controller** | 검증 실패의 원인 단계로 되돌아가 제한된 횟수 안에서 수정·재검증한다. |

정보를 **보존할지**, **어디에 둘지**, **어떻게 표현할지**를 분리한다. 예를 들어 `KEEP`은 현재 문장의 위치나 표현을 고정한다는 뜻이 아니다. 벡터 검색은 향후 목적지·중복·충돌 후보를 찾는 보조 수단이며, 유사도가 곧 정답은 아니다.

## 5. 검증 및 추진 계획

PR #15까지 추출·분석/의미 검증·배치 계획·표현 Preview·전체 후보 재구성/구조 검사·안전 중단이 구현됐다. 전체 출력 의미 검토·최종 승인·자동 수정 루프·파일 적용은 미완료여서 결과는 REVIEW를 유지한다. 정식 M0~M4 완료 판단과 다음 우선순위는 [로드맵](roadmap.md)을 따른다.

현재 합성 예시 12건과 공개 저장소 기반 실제 평가 후보 20건을 확보했다. 기존 20건은 이미 평가 기준 수립에 사용했으므로 **개발·회귀용으로 유지한다. 라벨은 잠정 상태이며, 독립 사람 검토·독립 평가를 위한 별도 홀드아웃 확보·성능 측정은 미완료**다.

| 단계 | 계획 |
| --- | --- |
| **M0** | 개발·회귀용 실제 사례의 독립 검토와 평가 기준 확정, 별도 사례로 독립 평가용 홀드아웃 확보·고정 |
| **M1** | Writing Contract, 규칙 기반 검증, 구조화 결과 및 CLI |
| **M2** | 정보 추출·분석과 재배치의 의미 검증 |
| **M3** | 표현 수정, 제한된 수정 루프, 전체 문서 재검증 |
| **M4** | 선택적 MCP·에이전트·편집기 연동과 비교 평가 |

동일 원문·계약에서 직접 작성(B0), 프롬프트만 개선(B1), LogicWrite 적용(B2)을 비교할 계획이다. 주요 지표는 독자 과업 달성, 필수 정보 보존, 모순 탐지의 정밀도·재현율, 수정으로 발생한 오류, 검토 소요 시간이다. **글자 수 감소 자체를 성공 지표로 삼지 않는다.**

## 6. 기대 효과와 차별성

문장 교정을 넘어 **정보 선택 → 구조화 → 표현 → 독립 검증**까지 책임을 구분한다. 문서 목적 오판 복구, 정보 단위별 판정, 출처와 조건의 양방향 추적, 필수 검사 누락 시 통과 금지가 핵심 차별점이다. 실제 품질 향상 여부는 평가 이후에만 주장할 수 있다.

## 7. 범위와 장기 방향

첫 구현은 한국어 기술 문서를 대상으로 하며 특정 LLM·벡터 DB에 종속되지 않도록 설계한다. 자동 배포, 무검증 사실 확정, 모든 ChatGPT 응답의 강제 가로채기는 초기 범위 밖이다. 장기적으로는 같은 엔진을 **에이전트 대화 응답의 정보 선별·순서·분량 검증**으로 확장하는 방향을 검토한다.
