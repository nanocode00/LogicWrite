# 전체 기능 Golden Set 확장안

검토용 제안 · 2026-11-13 · 기준 `origin/main` = `f86af9b964a077c60aee0a86ba613d612765b0bb`.
이번 변경은 조사·기획뿐이다. 신규 입력·정답·실행기·활성 등록을 만들지 않는다.

## 1. 범위와 설계 선택

기존 [평가 정책](evaluation.md)의 입력/정답 분리·문맥별 판단·B0/B1/B2 조건을 재사용한다. [Writing Contract](requirements.md#2-작성-계약writing-contract), [모듈 책임](architecture.md#핵심-모듈), [실행 인터페이스](data-model-and-interfaces.md#current-runtime-interfaces), [최종 승인 정책](final-approval-policy.md)은 각각 원래 문서가 소유한다. 아래 필드는 **평가 전용 논리 스키마 제안**이며 Core 입력이나 새 게이트 정책이 아니다.

| 접근 | 장점과 한계 | 제안 |
| --- | --- | --- |
| 기존 의미 보존 사례만 증대 | 회귀 비교는 쉽지만 무엇을 선택하고 어떻게 개선할지 측정하지 못함 | v3 회귀로 유지 |
| 대표 액션별 단일 정답 | 집계는 쉽지만 KEEP+배치+표현 공존, MOVE/통합 대안을 오답 처리 | 채택하지 않음 |
| 능력별 제약 정답 + 의사결정/결과 이중 평가 | 검수 비용은 늘지만 다른 올바른 구성과 실패 원인을 구별 | 파일럿으로 타당성 검토 후 채택 여부 결정 |

평가 단위는 **고정 계약과 문서 묶음으로 정의한 과제**다. 유형은 능력 태그이며 새 파이프라인 단계가 아니다. 한 과제에 주유형 1개와 부유형을 붙이되 유형별 분모를 공개하고 총 독립 사례 수에서 중복 계산하지 않는다. 목적이 바뀌면 별도 과제·계약 버전이며 이전 정답을 복사하지 않는다.

## 2. 유형과 경계

공통 입력 I = 독자·과업·문서 역할·명시 요구/가정·원문 및 필요한 문맥의 고정 스냅샷·출처/해시·가용성·편집 허용 범위. 모든 유형에 근거 있는 무수정과 반례를 포함한다.

| 유형 / 책임 | 평가 목적·추가 입력 | 정답 구조·허용 대안 | 판단 불가 조건 | 주요 지표 |
| --- | --- | --- | --- | --- |
| T1 분석 / Extraction & Analysis | 정보·조건·수치·귀속·관계와 목적 충돌 식별. I + 권위/시점 정보 | 원문 범위↔사실/관계 그래프, 충돌 쌍, 의도 근거. 동등한 단위 분할 허용 | 주체·시점·권위/목적 미확정 | 사실/관계 precision·recall, 근거 정합률, 거짓 모순률 |
| T2 선택·보존 / Analysis | 해당 독자에게 필요한 정보와 현지 노출 판단. I + 출력별 의무 | 필수/유용/선택·관련성·보존 장소·노출 제약. KEEP와 선택적 윤문/배치 공존 | 독자 과업 충돌, 현지 노출 의무 미확정 | 필수 정보 recall, 부적합 정보 잔존율, 과잉 수정률 |
| T3 제거 / Analysis→Organization | 정보를 없애도 되는지와 근거 평가. I + 중복 원본/보존 범위·제거 권한 | 제거 가능 범위와 금지 조건. 삭제·적절한 축약·무수정이 계약상 동등하면 모두 허용 | 보존 의무/중복 위치 미확인, 유용성만 낮음 | 부당 제거율, 제거 대상 검출 precision·recall, 고유 정보 손실률 |
| T4 문서 간 이동 / Organization | 적합한 소속·이동 전제·양쪽 보존. I + 목적지 전체·역할·링크·범위 권한 | 목적지 후보 집합과 조건, 원본 잔류/현지 노출 의무. 여러 목적지·요약+링크 허용 | 목적지/권한/전체 결과 부재 | 목적지 적합률, 양쪽 의무 충족률, 미확인 이동 강행률 |
| T5 문서 내 배치 / Organization | 독자 과업 순서·선행조건·그룹화. I + 섹션/앵커 | 부분 순서 제약과 그룹 경계. 제약을 충족하는 순열·제목 대안 허용 | 앞뒤 문맥/앵커 미제공 | 선행조건 충족률, 잘못된 순서 쌍 비율, 탐색 과업 성공률 |
| T6 중복 통합 / Organization | 동등 정보 통합과 고유 조건·귀속 보존. I + 모든 통합 후보 문맥 | 통합 가능/금지 쌍, 고유 사실의 다대다 추적. 통합 위치·분할·필요한 반복 허용 | 범위/시점/귀속 동등성 미확인 | 통합 쌍 precision·recall, 고유 조건 유지율, 잔존 불필요 중복률 |
| T7 보완 / Analysis→Organization→Expression | 누락 탐지와 근거 있는 ADD. I + 계약 요구·권위 있는 추가 자료 | 누락 의무↔근거↔삽입 위치/표현 제약. 사실 동일한 문구·위치 허용 | 요구만 있고 사실 근거 없음, 출처 충돌 | 누락 recall, 근거 있는 보완 precision, 허구 추가율 |
| T8 표현 / Expression | 명확성·문체·용어·압축 개선. I + 제외 구간·표현 제약 | 필수 교정/선택 개선·보호 요소·금지 변형. 여러 자연스러운 표현/무수정 허용 | 의미 판별 문맥/목표 문체 부족 | 제약 위반률, 의미 퇴행률, 독립 명확성/유용성 평정 |
| T9 전체 문서 / 세 모듈+독립 최종 검증 | 전체 구성·일관성·독자 과업 달성. I + 모든 영향 문서와 독자 질문/과업 | 필수 내용/노출·문서 역할·과업별 답/성공 기준·루브릭. 여러 완성 문서 허용 | 일부 출력 절단·필수 문서 부재·과업 불명확 | 과업 성공률, 문서 적합성 평정, 문서 간 충돌/퇴행률 |

T3은 보존 가치 있는 정보의 단순 이동과 다르다. T5는 같은 문서 안의 배치이며 MOVE가 아니다. T6은 보고용 8번째 액션을 신설하지 않는다. 기존 7개 액션과 내부 `CONSOLIDATE`의 차이는 실행 인터페이스를 따른다. T7은 Expression이 사실을 창작하는 권한이 아니다. T9에서 의미 보존은 필수 축이지만 목적 적합성·탐색성·완결성을 대신하지 않는다.

Core의 Validation Gate·Revision Controller는 위 유형 전체에 걸친 **제어 회귀 트랙 C**로 분리한다. 고정 상태 전이 시나리오에서 검사 누락, 오래된 증거, 잘못된 원인 복귀·하위 무효화, 유한 종료, 승인 경계를 평가한다. 정답은 기대 진단/무효화/종료와 추적이며 거짓 통과율·책임 복귀 정확도·종료율을 보고한다. 문서 품질 점수나 사용자 승인으로 환산하지 않는다. 기존 테스트를 먼저 재사용하고 이 설계에서 새 정책·테스트를 구현하지 않는다.

## 3. 평가·라벨링 스키마 제안

| 영역 | 필드와 규칙 |
| --- | --- |
| 식별·계보 | `case_id`, `version`, `primary_type`, `secondary_types`, `subscenario_ids`, `complexity`(단순/복합), `risk`(일반/고위험), `source_family`, `parent_ids`, `construction`(실제/통제 파생/합성), `exposure_history`, `split`, 출처 권리·재배포 범위 |
| 모델 입력 | `task`, `contract`, `source_documents`, `destination_documents`, `supporting_evidence`, `availability`, `allowed_edit_scope`; 문서별 역할·버전·완전성·UTF-8 SHA-256·원문 범위. 권장 액션·정답/검수 이력은 제외 |
| 의사결정 정답 D | `obligations`(정보·보존 장소·노출·조건), `evidence_refs`, `relations`, `required_decisions`, `optional_decisions`, `acceptable_alternatives`, `forbidden_outcomes`, `unresolved_questions`; 판단별 적용 여부/불가 사유 |
| 결과 품질 정답 Q | `task_checks`, `whole_document_constraints`, `rubric_anchors`, `protected_facts`, `trace_requirements`; 참고 수정본은 비유일 예시로 별도 보관. 후보 문서 전체가 없으면 Q 미평가 |
| 검수·상태 | 평가자별 최초 판단·근거·노출 여부, 불일치·중재·사용자 결정·포함 승인 별도 기록. `draft → independently_reviewed → adjudicated → frozen`은 새 평가 자산의 제안 상태이며 기존 workflow/승인 필드 대체 아님 |

범위 좌표는 기존 UTF-8 해시와 Unicode codepoint `[start,end)` 관례를 따른다. 단위 ID/문장 문자열의 일치로 채점하지 않고 원문 근거와 사실/조건 대응을 확인한다. 서로 양립할 수 없는 대안은 **완전한 대안 묶음**으로 평가한다. 예를 들어 ‘원문 조건 유지’와 ‘주장 축소+근거 문서 보존’의 유리한 부분만 섞어 충족한 것으로 계산하지 않는다. 목록 밖의 타당한 답은 오답 고정 대신 별도 재심으로 보내고, 평가 후 정답 수정 시 버전과 이전 결과를 보존한다.

- **D: 편집 의사결정** — 원문과 계약에서 무엇을 보존·제거·이동·추가할지 평가한다. 필수 판단 충족, 금지 판단 발생, 근거 일치, 타당한 보류를 각각 집계한다.
- **Q: 최종 편집 결과** — 실제 전체 출력에서 의무·의미·문체·구조·독자 과업을 평가한다. 좋은 계획과 나쁜 실행, 나쁜 계획과 우연히 좋은 결과를 별도로 남긴다. D와 Q 평균 단일 점수는 만들지 않는다.
- **불가/미실행 분리** — 정답상 근거 부족(`unresolved`)은 유효 라벨이다. 모델 무응답·실행 오류·부분 출력은 `not_evaluated/incomplete`이며 정답 보류 적중으로 세지 않는다. 항목별 부분 평가와 전체 완료 여부를 함께 보고한다.

### D를 실제로 관측하는 방법

D는 내부 사고과정 추정이 아니라 **외부로 제출한 편집 판단과 근거**를 평가한다. 결과물 Q만 보고 선택 이유·보류 의도를 복원하지 않는다. 관측 경로를 `native_trace / declared_plan / output_effect`로 구분한다.

| 조건 | 기존 실행에서 얻는 관측 | D 비교 실험에서 제출할 관측 |
| --- | --- | --- |
| B0 직접 작성/보조 없는 초안 | 전체 결과와 diff의 `output_effect`만 관측 가능. 별도 계획이 없으면 D 판단/근거는 미관측 | 동일 원문 편집 과제에서 공통 양식의 `declared_plan`을 먼저 제출하는 **B0-D 별도 변형**. 일반 작성 지시 외 LogicWrite 분석 지침은 주지 않음 |
| B1 프롬프트 보완 | 결과와 diff, 원래 응답에 명시한 판단만 관측. 사후 설명을 최초 결정으로 간주하지 않음 | B0-D와 같은 제출 양식에 기존 간결함·일관성·독자 적합성 지시만 추가한 **B1-D** |
| B2 LogicWrite | 분석 assessment·Organization placements/consolidation·Expression operations/findings의 `native_trace`, 최종 전체 결과·검증 기록 | 실행 전 공통 양식으로 매핑하고 원본 산출물 경로/필드·입력 해시를 연결. 최종 결과 뒤에 정당화 기록을 새로 생성하지 않음 |

공통 D 제출 항목은 대상 원문 범위/정보, 처리(유지·제거·이동·배치·통합·보완·표현·보류), 목적지/상대 순서/통합 대상, 보존·현지 노출 의무, 근거 위치, 필수/선택 판단, 미해결 질문이다. 정답의 의무 목록·액션·대안은 제공하지 않는다. 계획 제출 시점에 해시로 고정한 뒤 편집을 실행하며, 계획 변경은 시간순 별도 버전으로 남긴다. B2 자동 매핑의 누락/오해는 표본 원본 대조로 검수하고 원본에 없는 이유는 채우지 않는다.

**두 실험을 혼합하지 않는다.** 자연 실행 B0/B1/B2의 Q 비교는 유지하고, D의 공정한 비교는 동일 원문·계약·자료·제출 양식·응답 예산을 제공하는 B0-D/B1-D/B2-D 별도 실험으로 보고한다. 계획 제출이 결과에 미치는 영향도 제한으로 명시한다. 새 문서 생성 B0는 같은 원문의 편집 D 비교에서 제외한다. 자연 실행에 D 근거가 없으면 미관측이며 오답/정답으로 환산하지 않는다. diff로 확인되는 삭제·이동 등은 `output_effect` 보조 통계로만 보고한다.

사람 평가자는 고정된 제출 판단을 D 정답과 대응시켜 의무 누락·금지 판단·근거 일치·타당한 보류를 채점한다. Q 평가자는 그 계획을 보지 않고 전체 문서를 평가한 뒤 D/Q 대응을 분석한다. 추론된 무수정과 명시적 유지 판단, 계획상 이동과 실제 이동, 근거 없는 액션 일치는 구별한다. 원래 실행의 미관측 비율과 D 실험의 제출 완료율을 조건별 공개한다.

precision = 근거/제약상 타당한 제안 ÷ 평가 가능한 모든 제안, recall = 충족한 필수 의무 ÷ 고정된 필수 의무다. 부당 제거·허구 추가·과잉 수정률은 각각 해당 편집 기회/제안 수를 분모로 명시한다. 분모 0은 N/A, 누락 응답은 별도 완료율과 실패 수로 공개해 선택적 응답으로 점수를 높이지 못하게 한다. T5는 주석된 필수 순서 쌍만, T6은 검수된 비교 쌍만 분모에 넣는다. 누락된 필수 사실을 발견하면 정답 버전 재심 대상이다.

Q 루브릭은 적합성·탐색성·명확성·완결성을 각각 0(과업 방해/실패), 1(일부 가능하나 실질 보완 필요), 2(주요 과업 가능·경미한 결함), 3(요구 과업 충족)으로 평가하고 유형별 관찰 예시를 파일럿에서 고정한다. 평가자는 조건명을 가리고 동일 입력의 전후/B0/B1/B2를 무작위 순서로 본다. 보호 정보 손실·허구 추가 같은 중대 오류는 별도 표시하며 높은 문체 점수로 상쇄하지 않는다. 시간 측정은 시작/종료와 과업을 고정한 보조 지표다.

유형별 D/Q 분포·미평가율·중대 오류·정답 보류 적중/과잉 보류를 보고한다. 독립 출처 가족 수와 가족 단위 신뢰구간을 함께 공개한다. 단일 사례 파생을 독립 표본으로 부풀리지 않는다. 소규모 파일럿 점수는 성능 확정이나 Core PASS의 근거가 아니다.

### 충분성 판단

36/108건은 예산 기준이며 충분성의 증거가 아니다. 커버리지 장부는 `유형×하위 상황×단순/복합×위험×출처 가족×split`별 실제 건수와 근거 포인터, 검수 상태, 남은 공백을 공개한다. 모든 축의 전체 조합을 강제하지 않고 적용 불가 조합은 이유를 검수한다.

- **P2 파일럿 충분성:** 4건은 양식·판단 경계의 결함을 찾는 최소 시작점이다. 모든 필수 하위 상황을 검토해 커버/미커버를 표시하고, 단순·복합·고위험을 적어도 한 번씩 관측한다(중첩 가능). 부족하면 유형별 건수를 늘리며 4건으로 유형 커버 완료를 선언하지 않는다.
- **P3 동결을 검토할 최소 조건:** 적용되는 필수 하위 상황마다 최소 2개 독립 가족의 검수 과제, 유형별 단순·복합 각각 최소 2가족, 고위험 최소 2가족을 확보한다. 타당한 변경·무수정/금지 반례·복수 대안·정답 보류도 유형별 확인한다. 개발/홀드아웃 각각에 핵심 하위 상황과 복합·고위험을 배치하되 미커버 상황은 해당 split의 평가 주장 범위에서 제외한다. 이 조건이 12건으로 불가능하면 증원하거나 범위를 좁힌다.
- **검수 가능성:** 독립 평가자가 같은 근거로 의무·대안·보류를 구별할 수 있고, 미중재 이견·입력 결손·미확인 권리가 없어야 한다. 제안 최소 건수 충족만으로 통계적 충분성이나 모델 성능을 확정하지 않는다.
- **성능 주장에 필요한 충분성:** P2 결과로 평가 단위·가족 내 상관·관측 가능률·중대 오류를 확인한 뒤, P3 수집 전에 유형/위험별 허용 오차·신뢰수준·중대 오류 허용 상한과 표본 계획을 별도 승인·고정한다. 홀드아웃을 열어 필요한 수를 역산하지 않는다. 계획된 정밀도를 얻지 못하면 가족 수/구간과 탐색적 결과로 제한하고, ‘충분한 골드셋 완료’로 보고하지 않는다.

확장 전 다양성 장부에 문서 유형(최소 5종), 독자(초보 사용자/유지보수자/리뷰어/의사결정자), 목적(수행/검토/선택/기록), 한국어·영어 혼합, 짧은/긴 문서, 단일/다중 문서, 표·코드·인용·링크, 중대/미세 오류를 교차 기록한다. 한 유형의 문서·독자 편중과 빈 교차 칸은 수보다 먼저 보완한다. 확장 때 유형당 최소 3개 출처 가족, 전체 최소 12개 가족, 한 가족이 한 유형의 1/3을 넘지 않는 것을 잠정 목표로 둔다. 달성하지 못하면 제한된 개발 평가로 남긴다.

**출처 독립성:** 가족 키는 저장소 이름만이 아니라 프로젝트·원문·작성 조직·공유 템플릿·번역/포크·파생/변이의 연결 성분이다. 동일 원문 수정본·계약 대조 쌍·후보 생성 변형은 한 가족이다. 기존 RW 5개 저장소도 같은 소유자 편중을 별도 표시한다. 공개 사용/라이선스·NOTICE·재배포 허용을 확인하고 개인정보/비밀 자료는 수집하지 않는다. 현재 단계에서는 원격 대량 수집을 하지 않았다.

**홀드아웃:** 기존 29/RW20/LW12와 설계·프롬프트 튜닝에 노출된 모든 파생은 development다. 새 출처 가족을 주석/모델 시험 전에 가족 단위로 개발/홀드아웃에 배정한다. 독립 보관자가 미공개 입력·정답을 관리하고 접근 로그를 남긴다. 파일럿 사례는 전부 개발이다. 문구 유사도와 출처/부모 그래프를 함께 검사하며 유사도만으로 독립성을 확정하지 않는다. 홀드아웃 오류를 보고 튜닝하면 해당 버전은 노출 처리하고 새 가족으로 교체한다. 평가 결과를 보고 분할을 유리하게 바꾸지 않는다.

P2는 비율 합격선을 두지 않는다. 유형당 4건에서 사례 단위 일치율은 25%씩 변하므로 80% 기준은 사실상 4/4를 요구하고 안정적 신뢰도를 입증하지도 못한다. D는 사례별 필수/금지/보류 판단의 최초 일치·불일치와 원시 분자/분모를, Q는 평가자별 원점수·차이와 근거를 기록한다. 여러 항목을 잘게 나눠 독립 표본 수를 늘린 것처럼 집계하지 않는다. 우연 보정 지표·일치도 합격선은 이 파일럿의 통과 조건으로 쓰지 않는다.

파일럿 통과는 입력 완전성·정답 근거·대안/오답/불가 조건, 하위 상황 공백 장부, D 관측 가능성 및 사례별 이견 처리로 판단한다. 모든 이견을 자료 결손/유형 경계/루브릭 모호성/평가자 실수/유효 대안으로 분류한다. 미중재 중대 이견은 0건이어야 하며, 기준을 바꾼 항목은 별도 새 사례로 독립 재검수한다. 같은 쟁점이 재발하면 해당 유형 확대를 멈추고 기준을 수정한다. 중재 후 일치를 독립 최초 일치로 덮어쓰지 않는다. 이후 더 큰 개발 표본에서 일치도 추정의 단위·정밀도·판단 기준을 사전 고정하고 신뢰구간과 함께 검토하며, 유형 전체를 합쳐 희소 하위 상황의 불일치를 숨기지 않는다.

각 유형에서 타당한 대안/무수정이 통과하고, 의미 보존만 한 부적합 문서·유창하지만 정보 손실한 문서·판단 불가를 강행한 답이 서로 구별되는지 확인한다. 정답 노출·출처 미확인·미중재 불일치·범위 불명확이 남은 건은 동결 제외한다. 두 독립 사람을 확보하지 못하면 단일 사용자+AI 보조 개발 자료로 명시하고 독립 검수/홀드아웃 완료를 주장하지 않는다. AI 반례는 사람 평가자 수에 포함하지 않는다.
