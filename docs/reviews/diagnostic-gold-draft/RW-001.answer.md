# RW-001 진단용 정답 초안

상태: **사용자 검토 전 초안**. 개발·회귀용 진단 과제의 구성 예시이며 골드 고정·스키마 채택·독립 사람 승인·전체 문서 PASS가 아니다. 이 초안만 별도 작성했고 기존 후보와 재검토 장부는 보존했다.

입력은 [RW-001.input.json](RW-001.input.json)만 모델에 제공한다. 이 답안은 평가자용으로 분리한다. 입력 파일 SHA-256: `f7256434ef3780caf6d1863185f2100ee9035b0c8f4adbc1ebe9b3f5abc0d960` (파일의 실제 UTF-8 바이트, 마지막 줄바꿈 포함). 출처는 입력에 고정된 commit/blob과 구간으로 대조하며, URL의 현재 내용이나 이번 대화의 기억을 추가 입력으로 사용하지 않는다.

## 1. Information Extraction & Analysis

이 답안은 기존 세 모듈에서 기대하는 중간 판단과 공통 검증 시 확인할 사항을 기록한다. 여섯 차원은 각 모듈의 판단 항목이며 별도 처리 단계가 아니다. 필수 조건·허용 대안·오답 조건·미확정 사항은 평가자의 해석 기준이며 새 엔진 필드가 아니다. 최종 문서 수정과 Validation Gate까지 이어지는 설계 중 이 사례가 평가하는 범위는 중간 판단이다.

아래 U1–U4는 평가자가 사용할 참조 분할이다. 문장 수·단위 ID의 일치가 아니라 주장·조건·출처의 누락 여부를 평가한다. 다른 분할도 동일한 정보를 구별하고 조건을 연결하면 허용한다. 원문 제목도 선택 이유를 설명하는 문맥으로 읽는다.

| 참조 단위 | 원문 위치 | 보존할 정보 | 문맥상 기능 |
| --- | --- | --- | --- |
| U1 | target L78–80 | 이번 릴리스에서 PKG를 택한 근거: Applications 메뉴 막대 runtime, Node/cloudflared 번들, non-blocking 설치 후 Doctor | 요구사항을 근거로 한 패키징 선택 정당화 |
| U2 | target L81 첫 문장 | PKG가 초보자의 install and open 흐름을 더 명료하게 한다는 원문의 평가 | 선택의 기대 이점; 독립 사용성 검증 결과가 아님 |
| U3 | target L78–79의 DMG 절 | DMG는 drag-and-drop 앱에 적합하다는 비교 | 대안 평가 |
| U4 | target L81 둘째 문장–82 | signed/notarized DMG를 나중에 추가할 수도 있다는 가능성 | 미래 가능성; 현재 제공·확정 일정이 아님 |

U1과 U3는 같은 행에서 서로 다른 절을 참조한다. 단위를 분리해도 요구사항과 그 요구가 뒷받침하는 이번 릴리스의 선택 관계는 유지해야 한다. 모든 단위는 원문의 주장으로 다루며 실제 설치 동작을 새로 입증한 사실이 아니다.

### 관련성·중요도·정보 보존

이 표는 U1–U4 모두에 적용한다. 현재 출력 범위는 입력에서 정한 첫 설치 사용자용 README 시작 안내다. 아래의 관련성·중요도 판단을 모든 README나 목적지 문서에 일반화하지 않는다.

| 차원 | 참조 판단 | 필수 여부와 허용 범위 |
| --- | --- | --- |
| 관련성 | 설치 행동 안내에 직접 필요한 정보라기보다 선택 근거·대안·미래 가능성이다. 패키징 의사결정 기록에서는 관련성이 있다. | 기능·용도를 설명하는 판단 근거가 필수다. 문서 전체와 전혀 무관하다는 전칭 판단이나 정해진 표현 하나를 요구하지 않는다. |
| 중요도 | 현재의 설치 시작 과제에는 필수 정보가 아니다. 선택 근거로 보존할 가치는 있다. | 비필수라는 판단과 낮은 중요도를 이유로 임의 삭제하지 않는 구분이 필요하다. 세부 등급명 자체의 일치는 요구하지 않는다. |
| 정보 보존 | 주장·조건·원문 평가·가능성은 보존하되 현재 문서에 모두 노출할 의무로 보지 않는다. | 특히 non-blocking, 이번 릴리스 한정, signed/notarized DMG의 가능성을 누락하거나 확정 사실로 바꾸지 않는다. |

오답은 설치 요소가 언급됐다는 이유만으로 설치 절차라고 분류하거나, 길이가 짧고 순서가 자연스럽다는 이유만으로 유지하거나, 낮은 중요도만으로 정보를 폐기하는 판단이다. 의미가 같은 다른 단위 분할·등급 표현은 허용한다.

## 2. Information Organization

분석에서 확인한 보존할 정보와 조건을 바탕으로 현재 노출·목적지·배치를 판단한다. 이 사례에서는 실제 목적지와 기존 내용·독자·목적이 미확정이다.

| 차원 | 참조 판단 | 필수 여부와 허용 범위 |
| --- | --- | --- |
| 문서 간 이동 | 패키징 의사결정·설계 이력을 맡는 문서 역할로 분리하는 후보가 타당하다. | 실제 경로와 문맥이 없어 완료·원문 제거는 보류한다. MOVE 후보+미확인 사유, 또는 목적지 확인을 요청하는 FLAG/REVIEW 등 설명이 동등하면 허용한다. |
| 문서 내 배치 | 현재 문서의 다른 설치 절차 앞으로 옮기는 것만으로 선택 근거의 소속 문제를 해결하지 않는다. 목적지 안의 순서는 문맥 확인 후 정한다. | 목적지에서 요구사항·대안·선택 근거를 연결하는 구성은 예시다. 존재하지 않는 heading/anchor를 확인했다고 단정하지 않으며 하나의 순서를 강제하지 않는다. |

패키징 기록을 맡는 동등한 목적지 역할과 목적지 검토 전 임시 원문 보존을 허용한다. 임시 보존은 선택 근거를 현재 시작 안내에 영구 KEEP해야 한다는 판단과 구별한다. 목적지 확인·이동 완료를 꾸며내거나 현재 문서의 재배치를 문서 간 MOVE라고 보고하면 오답이다.

## 3. Expression Refinement

앞선 보존·조직 판단에 따라 다룰 정보와 조건을 유지하면서 표현을 검토한다. 목적지 확인이 보류된 상태에서 최종 수정 문서나 이동 완료본을 요구하지 않는다.

| 차원 | 참조 판단 | 필수 여부와 허용 범위 |
| --- | --- | --- |
| 표현 | 의미를 보존한 원문 유지·REVISE·COMPRESS 모두 가능하다. | 표현 수정은 선택 사항이다. 분리·보존 판단을 문장 축약만으로 대체하거나 조건을 지우면 안 된다. |

원문 유지와 조건을 보존한 표현 개선은 모두 허용한다. non-blocking·이번 릴리스 한정·원문의 평가라는 성격을 지우거나, future DMG를 현재 제공·확정 계획으로 바꾸면 오답이다.

## 공통 검증에서 확인할 사항

아래는 ValidationPlan에 따른 수작업 검토 시 확인할 기대 사항이다. 실제 검증 엔진을 실행한 결과나 ValidationReport가 아니다.

- **정보·출처 보존:** U1–U4에 해당하는 주장과 조건이 빠지지 않고 원문 위치에 대응하는지 확인한다. 다른 단위 분할도 같은 기준으로 검토한다.
- **모듈 간 일관성:** 정보 보존·현재 노출·이동 후보·표현 수정이 구별되고, 앞선 분석의 조건이 조직·표현 판단에 이어지는지 확인한다.
- **의미 왜곡:** 원문의 사용성 평가나 미래 가능성을 검증된 사실·현재 제공·확정 일정으로 바꾸지 않았는지 확인한다. 실제 설치 실행 성공을 꾸며내면 오답이다.
- **추가 증거 필요:** 실제 목적지와 기존 내용·독자·목적, 중복·통합 후 조건 보존, 이동 후 README 전체의 안내 충족 여부는 이 입력만으로 확인할 수 없다. 해당 불확실성을 드러내야 하며 전체 문서 PASS를 선언하지 않는다.

## 승인 범위

사용자가 승인할 대상은 **선택한 입력 문맥·사용자 목적의 표현과 위 정답 경계**다. 과거 대화에서 판단 방향을 합의한 사실과 이 입력/답안 초안 자체의 최종 승인은 구별한다. 독립 검수와 자동 검증 엔진 실행은 미수행이며, 나머지 19건의 답안을 승인하거나 골드 전체를 고정하는 효과는 없다.
