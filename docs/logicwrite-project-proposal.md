# LogicWrite 프로젝트 기획서

> **목표·선택형 확장 기획 · 현행화 2026-11-10 (PR #15 기준).** 실행 API와 회귀 수치는 [현재 실행 인터페이스](data-model-and-interfaces.md#current-runtime-interfaces), 일정이 아닌 완료 기준과 우선순위는 [로드맵](roadmap.md)을 기준으로 한다.

## 1. 프로젝트 개요

**프로젝트명:** LogicWrite — 문서의 논리적 구조와 의미를 검증하는 AI 글쓰기 개선 시스템

**목표:** AI가 작성한 문서의 정보 중복, 논리적 모순, 불필요한 내용, 부적절한 구성 및 표현 문제를 분석하고, 원문의 의미를 보존하면서 독자와 목적에 적합한 문서로 개선한다.

**주요 대상:** README, 기술 문서, 기획서, 보고서 등 개발자 및 AI 에이전트가 작성하는 문서

## 2. 목표 기능

LogicWrite는 세 가지 주요 모듈과 공통 검증 체계로 구성된다.

| 모듈 | 주요 역할 |
|---|---|
| 정보 추출 및 분석 | 문서의 주장·조건·수치·관계를 추출하고 중요도와 적합성을 평가 |
| 정보 재구성 | 중복 정보 통합, 불필요한 내용 제거, 문서 간 정보 이동 및 순서 재배치 |
| 표현 개선 | 문장 간결화, 문체·용어 통일, 가독성 개선 및 의미 보존 |
| 검증 및 수정 제어 | 의미 왜곡·정보 누락을 검증하고 오류 발생 시 해당 단계로 복귀 |

사용자의 작성 목적과 대상 독자를 **Writing Contract**로 관리하며, 각 단계의 결과를 독립적으로 검증한다.

## 3. RAG 및 LangGraph 적용 계획

기존 핵심 기능과 분리된 선택형 확장 모듈로 구현할 계획이다. **RAG·LangGraph 코드는 아직 없다.** 아래는 지원 중인 API가 아니라 [과제 트랙 설계](rag-langgraph-assignment-design.md)의 목표다.

### RAG — 문서 간 근거 검색 및 보완

프로젝트 내 여러 문서를 검색하여 문서 간 모순과 누락된 정보를 탐지하고, 검색된 근거를 바탕으로 수정안을 생성한다.

- 문서 수집 및 청크 단위 인덱싱
- 키워드·벡터 기반 하이브리드 검색
- 문서 간 모순·중복·누락 정보 탐색
- 출처와 원문 위치를 검증한 근거 기반 수정안 생성

### LangGraph — 문서 처리 워크플로 관리

각 분석·검증·수정 모듈을 상태 기반 그래프로 연결하여 실행 흐름을 제어한다.

- 단계별 상태 관리 및 조건부 실행
- 검증 실패 시 해당 단계로 복귀
- 재시도 횟수 제한 및 반복 오류 중단
- 체크포인트를 이용한 실행 중단·재개
- 검토가 필요한 결과의 별도 처리

**설계 원칙:** RAG는 근거를 제공하고 LangGraph는 실행을 제어한다. 최종 검증 권한은 기존 LogicWrite의 검증 모듈이 유지한다.

## 4. 현재 개발 현황

| 구성 요소 | PR #15 기준 상태와 한계 |
|---|---|
| 요구사항·아키텍처·데이터 모델 | 설계 문서 존재. 정식 실행 스키마·평가셋 동결 미완료 |
| 계약·정보 추출 및 분석 | 단일 구체적 scope·전체 스냅샷 검증, 모델 응답 조립과 출처 추적 프로토타입 |
| 의미 충실도 검증기 | 분석↔원문 독립 검토 구현. supported도 정책상 REVIEW; 수정 후 전체 출력 의미 승인과 다름 |
| 정보 재구성 | Organization 계획·목적지/조건 검사와 제한된 전체 문단 재배치·MOVE·동일 문단 통합 후보 구현 |
| 표현 개선 | 원문 범위 Preview·제한된 문체/용어/압축 및 독립 검증 구현. 범용 윤문 품질 미평가 |
| 최종 검증·수정 제어 | 전체 후보 구조·범위·추적 검사와 진단·무효화·재검증·중단. 자동 수정 루프·파일 반영 없음 |
| RAG·LangGraph 확장 | 별도 설계 초안만 존재. Core 검증 권한을 유지할 어댑터 미구현 |

회귀 테스트 합계와 의미 검증기 단독 테스트 수를 구분한다. 최신 실행 수치와 명령은 [인터페이스 문서의 검증 절](data-model-and-interfaces.md#현행화-근거와-검증)로 통합한다. 고정 의미 사례 14건과 과거 실제 LLM 기록은 개발·회귀 근거이며 독립 홀드아웃이나 범용 품질 보장이 아니다.

## 5. 향후 개발 계획

Core의 전체 출력 의미 검토·명시적 승인과 독립 평가를 먼저 보강하고, 일반 의미 재구성·유한 자동 수정/재검증·파일 반영 경계를 단계적으로 완성한다. 현재 최종 `semantic_fidelity: not_run`, `delivery_approved: false`를 확장 모듈이 덮어쓰지 않는다.

RAG·LangGraph 과제는 별도 트랙으로 포트 어댑터 → 상태·종료 제어 → 근거 검색/생성 → 비교 평가 순으로 준비한다. 제안된 `CorePort`를 기존 API와 같은 것으로 취급하지 않고, 미지원 승인 실행은 명시적으로 보류한다. 세부 우선순위의 단일 참조는 [로드맵](roadmap.md), 포트의 목표 계약은 [과제 설계](rag-langgraph-assignment-design.md)다.

## 6. 성능 평가 계획

동일한 문서를 대상으로 네 가지 구성을 비교할 계획이다. 현재 C0~C3 비교는 수행하지 않았으며 Core와 확장에 같은 계약·검사·승인 경계를 적용해야 한다.

- **C0:** 기존 LogicWrite
- **C1:** LogicWrite + RAG
- **C2:** LogicWrite + LangGraph
- **C3:** LogicWrite + RAG + LangGraph

평가 항목은 의미 왜곡 탐지율, 정보 누락·모순 탐지 성능, 근거 인용 정확도, 문서 개선 품질, 실행 안정성 및 처리 비용이다.

## 7. 기대 효과

단순한 문장 교정을 넘어 **정보의 정확성, 논리적 일관성, 문서 구성, 표현 품질을 함께 관리하는 AI 문서 개선 시스템**을 구축한다.

RAG를 통해 여러 문서에 분산된 정보를 활용하고, LangGraph를 통해 검증과 수정 과정을 체계적으로 관리함으로써 근거와 변경 이력을 추적할 수 있는 문서 개선 워크플로를 구현하는 것이 최종 목표다.
