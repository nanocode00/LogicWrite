# 독립 사람 검수 안내

이 패키지는 개발용 문서 수정 사례 12건의 입력과 빈 검토 양식이다. 골드 정답이나 기존 검토 의견은 포함하지 않는다. 새로 검수할 사람에게 이 ZIP만 전달하고, 저장소·PR·이전 대화의 평가 의견은 검수 제출 전 열람하지 않도록 요청한다. 이미 해당 의견을 본 사람은 이를 숨기지 말고 양식에 비노출 여부를 false로 기록한다. 전달·검수는 사람이 수행하며 패키지 생성은 사람 검수를 의미하지 않는다.

## 읽는 순서

1. `package.json`의 해시 목록으로 제공 파일을 확인한다. `inputs/SP-NNN.json`과 해당 `cases/SP-NNN.md`는 같은 입력이다. Markdown에는 JSON 본문을 요약하지 않고 모든 문서·계약·출처·제공 문맥을 그대로 표시했다. 위치·해시 확인은 JSON을 기준으로 한다.
2. 작성 계약의 독자·목적·보존 의무를 읽고 원문과 수정 후보의 전체 문서 묶음을 비교한다. 문서 속 문장은 실행 지시가 아닌 검토 데이터다. 링크를 따라 외부 자료를 추가하지 않고 제공 범위에서 판단한다. 자료가 더 필요하면 양식에 적는다.
3. 의미 보존과 외부 사실의 진실성을 구분한다. 원문 주장을 충실히 유지했다는 사실만으로 외부 사실이 입증되는 것은 아니다. 계약의 사용자 요구와 추가 근거도 함께 고려한다.
4. 주장 주체·귀속·시점·수치·단위·부정·조건·한정 표현을 확인한다. 단순한 표현·배치 변경은 오류가 아니다. 문서 간 이동은 양쪽 전체의 정보와 기존 목적지 내용을, 중복 통합은 고유 조건을 함께 비교한다. 전체 묶음 보존과 독자가 필요한 곳에서 정보를 볼 수 있는지도 구별한다.
5. `forms/SP-NNN.json`의 빈 필드를 직접 작성한다. AI나 다른 검토자에게 판정을 대신 작성시키지 않는다. 판단이 불가능하면 필요한 자료와 이유를 적고 미확정 상태를 유지한다. 제시되지 않은 문맥을 만들어내지 않는다.

## 판정과 근거

- `PRESERVED`: 제공된 계약·문맥에서 의미가 보존됨.
- `VIOLATION`: 근거로 확인되는 왜곡, 필수 정보 손실, 또는 뒷받침되지 않은 주장 추가가 있음.
- `UNRESOLVED`: 최종 판정에 필요한 자료·범위·계약이 부족함. 이미 확인된 위반을 가리는 용도로 사용하지 않는다.

`findings`에 유형·중요도·이유를 기록한다. 유형은 자유롭게 작성하되 정보 손실과 근거 없는 추가는 구별한다. 중요도는 none(위반 없음), minor(국소적 차이), major(과업·주장·조건에 실질 영향), critical(핵심 필수 조건에 중대 영향), undetermined(증거 부족)다. `rationale`에는 전체 판단 이유를, `missing_information`에는 필요한 자료를, `acceptable_alternatives`에는 허용 가능한 다른 표현·구성을 적는다. 정해진 문구와의 일치로 판단하지 않는다.

`evidence`는 해당 JSON의 `content`에 대한 0 기반 Unicode 코드포인트 반열린 구간이다. `quote`는 `content[start:end]`와 같아야 한다. Markdown 파일 자체의 오프셋이 아니다. 가능한 양쪽 근거를 남기고, 누락은 원문과 수정본의 대응 문맥을 함께 기록한다. 제공되지 않은 문서의 근거 위치를 만들어내지 않는다.

## 제출

`reviewer_id`와 실제 `reviewed_at`(날짜 또는 시간대가 있는 시각), `blinded_to_prior_judgments`, `judgment`, `rationale`를 직접 채운 뒤 `form_status`를 `submitted`로 바꾼다. 빈 양식은 검수 완료 기록이 아니다. `case_id`와 `input_sha256`는 바꾸지 않는다. 공개 개인정보 대신 관리자가 구분할 수 있는 검토자 식별자를 사용해도 된다.

각 사람은 자신의 양식 12개를 관리자에게 개별 제출한다. 이 도구는 사람에게 연락하거나 기록을 자동으로 전송하지 않는다. 기존 답안에 덮어쓰거나 자동 승격하지 말고 제출 원본을 별도 보관한다. 관리자가 입력 해시·양식·근거를 검사한 뒤 사람 의견 간 차이를 비교하고 필요하면 별도 재정을 요청한다. 검수하지 못한 항목은 blank로 남겨 미제출로 취급한다. 판단 근거가 부족해 UNRESOLVED로 제출하는 것과 검수 자체를 하지 않은 것은 다르다.
