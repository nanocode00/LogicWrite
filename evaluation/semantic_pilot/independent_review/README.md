# 독립 검수 준비 — 관리자용

이 문서는 관리자용이며 검토자 ZIP에 넣지 않는다. 기존 파일럿은 개발용·전건 `provisional`, `gold_eligible: false`다. 사용자 공동 검토는 실제 사람 검토로 보존하며, 독립 검토자나 재정자의 판단을 생성·기록하지 않는다.

## 기준과 보존

- 파일럿 기준: PR #17의 `289f4e55e89fee04ebe5207fd41f88084443b172`.
- 반영한 main: PR #18 병합 `d752c4b5c5e73faea8ad552a43f06845c6066f8c`. 로컬 main 병합 시 충돌 없음. `manifest.base_commit`은 파일럿 생성 당시 기준이므로 변경하지 않는다.
- [preserved-files.json](preserved-files.json)에 기존 입력 12·답안 12·manifest 1·스키마 2의 SHA-256을 고정했다. 사용자 검토 기록을 포함한 기존 27개 파일은 바이트 단위로 보존한다.
- AI 기대 판정 4/4/4와 사용자 판정 3/4/5를 합치지 않는다. SP-003의 차이는 그대로 유지한다. 이 패키지는 이미 개발 과정에 노출된 입력의 독립 사람 검수용이며 독립 홀드아웃이 아니다.

## 생성·배포

저장소 루트에서 기존 `evaluation/semantic_pilot/requirements.txt`의 환경을 사용한다.

```bash
python3 evaluation/semantic_pilot/validate.py
python3 -m unittest discover -s evaluation/semantic_pilot -p test_validate.py
python3 -m unittest discover -s evaluation/semantic_pilot/independent_review -p test_review_package.py
python3 evaluation/semantic_pilot/independent_review/export.py
```

로컬 산출물: `evaluation/semantic_pilot/independent_review/dist/independent-review-inputs.zip`. ZIP은 Git에서 제외하며 소스에서 결정론적으로 재생성할 수 있다. 패키지의 전체 SHA-256은 생성 명령이 출력한다. 내부 `package.json`은 제공 파일별 해시만 포함하고 기존 manifest는 포함하지 않는다. 같은 ZIP을 각 검토자에게 따로 전달하며 각자의 판정 제출 전 다른 사람의 의견을 공유하지 않는다. 이 작업에서는 배포·연락하지 않는다.

| ZIP 포함 | 제외 |
| --- | --- |
| 입력 JSON 12개, 전체 내용을 그대로 표시한 Markdown 12개 | AI 답안, 사용자 공동 검토, 사례별 예상 판정·해설 |
| 입력이 참조하는 고정 공개 원문 스냅샷 | 기존 manifest, 답안 스키마, 이 관리자 문서와 보존 장부 |
| 중립적인 REVIEWER.md, 입력 스키마 | PR 설명, 기존 검수 가이드·후속 쟁점 목록 |
| 검토 기록 스키마, 모든 사람 판단 필드가 null인 빈 양식 12개 | 모델/검증기 출력, 미리 채운 사람 판정, 재정 기록 |

검토자에게는 ZIP과 독립 검토 요청만 전달한다. 이미 AI·사용자 판단을 본 경우 독립 비노출 검토로 소급 표시하지 않는다. 입력 안의 계약과 `missing_context`는 원래 평가 입력이므로 그대로 제공한다. 이전 주석을 숨기려고 입력 문맥을 삭제하지 않는다. 아직 문맥 보완이 필요한 사례도 입력 그대로 판단하고 필요한 자료를 요청하도록 한다.

## 제출 기록 확인

각 사람은 자신의 `forms/SP-NNN.json`만 작성한다. 검수 전에는 `blank`, 제출 시 실제 검토자 식별자·시점·노출 여부·판정·이유·근거를 채우고 `submitted`로 바꾼다. 빈 양식과 완료 기록을 구분한다. AI는 사람 판정이나 재정 결과를 채우지 않는다.

```bash
python3 evaluation/semantic_pilot/independent_review/check_form.py /path/to/reviewer/SP-001.json
```

검사는 양식 스키마·입력 해시·근거 인용/범위와 필요한 기록을 확인할 뿐 사람 신원·실제 검토 여부·의미 정확성을 보증하지 않는다. false인 비노출 기록도 숨기거나 true로 바꾸지 않는다. 이 명령은 `answers`를 수정하거나 검수 상태를 승격하지 않는다.

제출 원본은 검토자별 별도 저장 위치에 보관한다. 관리자가 실제 검토자·검토 조건·입력 버전을 확인한 후, 후속 변경에서 새 `reviews` 기록을 추가하는 방식을 검토한다. 기존 사용자 기록을 교체하지 않으며 사람 간 불일치와 해결 근거를 남긴다. 독립 검토·필요한 재정과 포함 승인 전에는 골드로 승격하지 않는다. 독립 검토자·재정자는 아직 배정·실행되지 않았다.

## 후속 사람 확인과 비파괴 확장 제안

| 기존 사례 | 확인이 필요한 것 | 기존 사례를 보존한 확장 제안 |
| --- | --- | --- |
| SP-003·011 | 앱 핵심 기능, 첫 실행 시 오프라인 검색 필요성, 캐시 준비 시점, 조건을 놓친 영향, 현지 노출 의무. 링크 허용 계약 자체의 정당성과 두 사례 중복성 | 새 ID로 ‘첫 실행 필수 선행조건’과 ‘선택 기능 상세 조건’ 문맥을 각각 고정. 이동 전후 전체 문서와 역할을 제공하고 사람이 적절한 노출을 판단. 기존 SP-003 계약·AI 라벨·사용자 보류는 유지 |
| SP-009 | PACKAGING.md의 수정 전후 전체 스냅샷·역할, 링크 해소, 이동한 조건과 기존 목적지 정보 보존 | 새 ID로 목적지 전체를 제공한 결과를 작성. 후보 생성 후 사후 검증을 허용하되 링크 성공과 의미 보존을 각각 확인. 기존 목적지 미제공 사례는 그대로 보류 평가에 유지 |
| SP-010 | 실제 작성 시점, 적용 버전·대상 일치, 권한자의 기준 원문 승인. v2라는 이름만으로 최신·승인을 확정하지 않음 | 승인된 기준을 제공한 v1 기반·v2 기반 사례를 별도 ID로 구성. 후행 자료 우선 참고라는 사용자 의견은 보존하되 기준 확정은 사람에게 요청 |
| SP-012 | 절단되지 않은 최종 결과 전체·해시와 전송 범위 | 전체 결과에서 수동 재설치 조건이 남은 경우와 실제 누락된 경우를 별도 ID로 구성. 기존 절단 관측 사례와 추정 없이 비교 |

확장은 제안만 했으며 새 사례·정답은 생성하지 않았다. 필요 시 `SP-013` 이후의 충돌 없는 ID 또는 별도 확장 dataset에서 `parent_case_id`, 조건 변경 내용, 새 계약 버전·전체 문서 해시·독립 검수 기록을 관리한다. 현재 12건 manifest와 4/4/4 검사는 그대로 보존하고 확장용 manifest·검사를 별도로 둔다. 같은 원문/파생 계열의 사례는 개발용에 함께 두며 서로 독립 표본이나 홀드아웃으로 세지 않는다. 조건이 해결됐다고 기대 판정을 AI가 사람 정답으로 확정하지 않는다.

## 병합 준비 범위

목표는 개발용 잠정 자료·공동 검토 이력·독립 검수 준비 도구의 반영이다. 사람 골드 동결, 홀드아웃 완성 또는 Core 승인 정책 변경이 아니다. 기존 Core·승인 정책·fixture·파일럿 입력/답안/manifest/스키마는 변경하지 않는다. GitHub 충돌 여부와 로컬 검사 결과는 최종 PR HEAD에서 다시 확인하고 실제 병합은 별도 사용자 지시를 기다린다.
