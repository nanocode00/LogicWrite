# 사람 검수 순서와 사례별 확인 사항

세 사례의 사용자 제공 검수 결과와 IR-001·IR-002 수정요청 반영 결과를 [CHANGE_REQUESTS.md](CHANGE_REQUESTS.md)에 기록했다. IR-003의 초안 열람 전 최초 판단 원문, ChatGPT 제안 기준, 이후 초안 대조 검토와 사용자가 동의한 최종 판정을 구분해 기록했다. IR-001·IR-002의 최초 판단 상세 이력은 미확인이다. 독립 사람 반례·중재·골드 포함 승인 사실은 기록하지 않는다. 아래 체크는 검토할 질문이며 검수 완료 표시가 아니다.

1. [IR-001 입력](inputs/IR-001.md), [IR-002 입력](inputs/IR-002.md), [IR-003 입력](inputs/IR-003.md) 중 한 건만 연다. 답안과 이 페이지 아래의 사례별 진단은 최초 판단 후에 본다.
2. 해당 `reviews/IR-xxx.json`을 별도 사본으로 보관하고 입력 해시를 확인한다. `initial_judgment`에 문서 역할·문제·필요한 조치·보류를, `initial_evidence`에 근거 위치를 기록한다. AI 예시를 미리 봤다면 `answer_exposure`에 그대로 쓴다.
3. 최초 판단을 보존한 뒤 `answers/IR-xxx.md/json`과 비유일 전체 출력 예시를 연다. 필수 조건이 입력에서 도출되는지, 지나친 정답 강제가 있는지 반례를 쓴다.
4. 가능하면 다른 사람이 답안을 보지 않고 독립 검토한다. 그 과정·노출 범위를 남긴다. AI의 두 번째 검토를 독립 사람 검토로 기록하지 않는다.
5. `final_judgment`와 `adjudication`에 해결/미해결을 구분한다. 수정 필요 시 이전 입력·답안·판단을 보존하고 새 버전·해시로 재검토한다. `gold_inclusion_approval`은 null로 남긴다.

| 사례 | 답안 노출 후 점검할 질문 | 허용 대안과 위험 |
|---|---|---|
| IR-001 | README의 입구·참여 역할을 모두 고려했는가? 후원 안내와 내용이 충돌하는가? 초보자가 설치·경로 전제·경고를 찾는가? 기록의 배포 절차는 어떻게 보존되는가? | 설치 상세는 README 또는 사용 안내 링크 모두 가능. 기부 섹션 삭제를 요구하지 않는다. 읽기 전용 개발 기록을 수정한 이동은 불가. |
| IR-002 | 날짜·환경 차이를 구분하는가? 운영서만으로 중단·연락·재개 여부를 판단하는가? 관찰 수치를 현재의 일반 성능으로 과장하지 않는가? | 핵심 조건의 양쪽 반복과 주간 관찰 요약/링크 모두 가능. 500건 초과를 이상으로 바꾸는 조건 퇴행을 확인한다. |
| IR-003 | 원문이 이미 적절함을 인정하는가? 내용/서식 권한을 나눴는가? 회의와 공유 범위만 묻고 실험 수치는 다시 묻지 않는가? | 무수정 전체 원문이 정당하다. 형식 후보는 필요할 때만 가능. 정당한 보류와 파일 누락·실패·무응답을 구별한다. |

## 공통 검수 체크리스트

- [ ] 자연어 요청이나 제목이 정답 동작·수정 위치를 알려주지 않는가? 일반 권한과 정답 누설을 구별했는가?
- [ ] 명시 제약/추론 요구/근거 판단/확인 사항/실제 변경/최종 검증을 구별했는가?
- [ ] 모든 문서의 역할·독자·고유 정보가 보존되고 필요한 정보가 적절한 곳에 있는가?
- [ ] 단일 표현·위치·동작을 강제하지 않으면서 실제 독자 과업을 판별할 수 있는가?
- [ ] 문서군 전체와 읽기 전용 자료 사이에 새 충돌·중복·참조 오류가 없는가?
- [ ] 입력 공백이 의도된 보류 조건인지, 출제 결함인지 구별했는가?
- [ ] 원문 인용이 판단을 실제로 뒷받침하는가? 문자열 일치만으로 정답을 승인하지 않았는가?
- [ ] 합성·저작 군집·노출·사람 판단·포함 승인 경계가 정확한가?

공통 체크리스트 전체 완료를 뜻하지 않는다. 검증기 통과를 체크리스트 완료로 옮기지 않는다.

## 통합 정리 후 사람 검수 관문

[설계 제한](DESIGN.md#통합-정리에서-확인한-설계-제한-2026-11-13)을 먼저 읽는다. IR-001의 잡음 난도, IR-001/002의 역할 유도, Q 조건의 필요성/대안·정당한 무수정 및 부분 보류를 재심한다. 3건의 입력·답안·참고 출력은 v1을 보존했다. 최초 사람 양식과 이전 검수 기록은 reviews/history/에 보존하고 현재 검수 JSON은 승인된 판단을 기록했다. 이번 기계 검증은 사람 최종 판단이나 개발 골드 포함 승인이 아니다. `input-v2.schema.json`은 입력 규약이다. 별도의 [평가 기준 v2](criteria/v2/README.md)는 같은 v1 입력에 연결된 수정본이며 신규 사례가 아니다.

## 사용자 제공 검수 결과 및 후속 상태

| 사례 | 기록된 판정 | 수정요청 상태 | 검수 기록 |
|---|---|---|---|
| IR-001 | 평가 기준 수정 필요, 골드 포함 보류 | CR-001-01~CR-001-05 기준 v2 반영, 수정 후 사람 재검수 대기 | [JSON](reviews/IR-001.json), [상세 요청](CHANGE_REQUESTS.md#ir-001) |
| IR-002 | 조건부 통과, Q1 수정 후 재검증 필요, 골드 포함 보류 | CR-002-01 기준 v2 반영, 수정 후 사람 재검수 대기 | [JSON](reviews/IR-002.json), [상세 요청](CHANGE_REQUESTS.md#ir-002) |
| IR-003 | 사람 검수 통과, 기준 수정 불필요, 골드 포함 승인 보류 | 수정요청 없음, v1 기준 유지 | [JSON](reviews/IR-003.json), [상세 판단](CHANGE_REQUESTS.md#ir-003) |

스키마의 고정 상태값 `pending_human_review`는 유지한다. IR-003의 최초 판단은 초안 열람 이전, 이후 대조·반례 검토는 ChatGPT와 진행했다. 독립 사람 반례 검토로 집계하지 않는다. 확인되지 않은 시각·서명·승인은 기록하지 않는다.

[기준 v2 계보](criteria/v2/manifest.json)에 반영 위치와 원본 해시를 연결했다. IR-001·IR-002의 기존 사람 판단은 보존하고 수정 후 사람 재검수는 null/대기다. 검증 통과는 사람 재검수 통과를 뜻하지 않는다. v1 참고 출력은 새 기준의 적합 예시로 재승인하지 않았다. 세 사례의 `gold_inclusion_approval`은 null이며 골드셋 동결·모델 성능 평가·문서 발행은 수행하지 않는다.

clarification-01에서 IR-001 Q3의 근거 기록 위치는 제출물의 검토 기록·HITL 요청임을 명확히 했다. 현행 clarification-02 기준은 README에 내부 검토 의견·미확정 정책을 남기는 것을 허용하지 않는다. IR-003 최초 판단은 사용자 정정 원문으로 기록하고 공유 범위·실험 수치 재질문 금지는 ChatGPT 제안·AI 기준에 귀속했다. [정정 내역과 이전 기록](CHANGE_REQUESTS.md#clarification-01--기록-위치-및-판단-출처-정정)을 보존했으며 새 재검수 결과·골드 승인·검수 시각은 만들지 않았다.

## clarification-02 이후 AI 대조 및 참고 출력 후보

[비유일 v2 후보 및 AI 반례 검토](reference_outputs/v2_candidates/REVIEW.md)를 추가했다. IR-001은 원래 Donate·개발 이야기 문구를 유지하고 정책·일기성 정보 처리만 HITL로 남기면서 사용 안내·유지보수를 개선한다. IR-002는 정책 값을 운영서에 모으고 설계서에 한계가 있는 관찰을 남긴 B 후보다. 16개 반례의 AI 기대 판정을 기록했으며 사람 재검수·실제 판정기 실행 결과가 아니다. 후보별 자동 검사는 의미적 적합성을 승인하지 않는다. 기존 사용자 판단·검수 JSON·골드 승인·수정 후 사람 재검수 결과는 그대로 유지한다.
