# 사람 검수 순서와 사례별 확인 사항

현재 최초 판단·독립 사람 반례·최종 판정·중재·포함 승인은 없다. 아래 체크는 검토할 질문이며 검수 완료 표시가 아니다.

1. [IR-001 입력](inputs/IR-001.md), [IR-002 입력](inputs/IR-002.md), [IR-003 입력](inputs/IR-003.md) 중 한 건만 연다. 답안과 이 페이지 아래의 사례별 진단은 최초 판단 후에 본다.
2. 해당 `reviews/IR-xxx.json`을 별도 사본으로 보관하고 입력 해시를 확인한다. `initial_judgment`에 문서 역할·문제·필요한 조치·보류를, `initial_evidence`에 근거 위치를 기록한다. AI 예시를 미리 봤다면 `answer_exposure`에 그대로 쓴다.
3. 최초 판단을 보존한 뒤 `answers/IR-xxx.md/json`과 비유일 전체 출력 예시를 연다. 필수 조건이 입력에서 도출되는지, 지나친 정답 강제가 있는지 반례를 쓴다.
4. 가능하면 다른 사람이 답안을 보지 않고 독립 검토한다. 그 과정·노출 범위를 남긴다. AI의 두 번째 검토를 독립 사람 검토로 기록하지 않는다.
5. `final_judgment`와 `adjudication`에 해결/미해결을 구분한다. 수정 필요 시 이전 입력·답안·판단을 보존하고 새 버전·해시로 재검토한다. `gold_inclusion_approval`은 null로 남긴다.

| 사례 | 답안 노출 후 점검할 질문 | 허용 대안과 위험 |
|---|---|---|
| IR-001 | README의 입구·참여 역할을 모두 고려했는가? 후원 안내와 내용이 충돌하는가? 초보자가 설치·경로 전제·경고를 찾는가? 기록의 배포 절차는 어떻게 보존되는가? | 설치 상세는 README 또는 사용 안내 링크 모두 가능. 기부 섹션 삭제를 요구하지 않는다. 읽기 전용 개발 기록을 수정한 이동은 불가. |
| IR-002 | 날짜·환경 차이를 구분하는가? 운영서만으로 중단·연락·재개 여부를 판단하는가? 관찰 수치를 현재의 일반 성능으로 과장하지 않는가? | 핵심 조건의 양쪽 반복과 주간 관찰 요약/링크 모두 가능. 500건 초과를 이상으로 바꾸는 조건 퇴행을 확인한다. |
| IR-003 | 원문이 이미 적절함을 인정하는가? 내용/서식 권한을 나눴는가? 회의와 공유 범위만 묻고 실험 수치는 다시 묻지 않는가? | 무수정 전체 원문이 정당하다. 형식 후보는 필요할 때만 가능. 정당한 보류와 파일 누락·실패·무응답을 구별한다. |

## 공통 검수 체크리스트

- [ ] 자연어 요청이나 제목이 정답 동작·수정 위치를 알려주지 않는가? 일반 권한과 정답 누설을 구별했는가?
- [ ] 명시 제약/추론 요구/근거 판단/확인 사항/실제 변경/최종 검증을 구별했는가?
- [ ] 모든 문서의 역할·독자·고유 정보가 보존되고 필요한 정보가 적절한 곳에 있는가?
- [ ] 단일 표현·위치·동작을 강제하지 않으면서 실제 독자 과업을 판별할 수 있는가?
- [ ] 문서군 전체와 읽기 전용 자료 사이에 새 충돌·중복·참조 오류가 없는가?
- [ ] 입력 공백이 의도된 보류 조건인지, 출제 결함인지 구별했는가?
- [ ] 원문 인용이 판단을 실제로 뒷받침하는가? 문자열 일치만으로 정답을 승인하지 않았는가?
- [ ] 합성·저작 군집·노출·사람 판단·포함 승인 경계가 정확한가?

이 문서의 모든 항목은 아직 사람 검수 대기다. 검증기 통과를 체크리스트 완료로 옮기지 않는다.

## 통합 정리 후 사람 검수 관문

[설계 제한](DESIGN.md#통합-정리에서-확인한-설계-제한-2026-11-13)을 먼저 읽는다. IR-001의 잡음 난도, IR-001/002의 역할 유도, Q 조건의 필요성/대안·정당한 무수정 및 부분 보류를 재심한다. 3건의 입력·답안·사람 양식은 기존 v1 그대로다. 이번 기계 검증은 사람 최종 판단이나 개발 골드 포함 승인이 아니다. v2는 입력 규약만 추가했으며 사람 검수할 신규 사례를 생성하지 않았다.
