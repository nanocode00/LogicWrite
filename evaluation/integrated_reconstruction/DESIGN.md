## 설계 선택과 평가 단위

| 접근 | 검토 결과 |
|---|---|
| 기존 57건을 새 키로 자동 변환 | 동작 누설과 저작 군집을 그대로 복제할 위험 때문에 채택하지 않는다. |
| 공개 실제 편집 이력만 즉시 수집 | 장기적으로 필요하다. 지금은 실제 사용자 맥락·권한·권리·원문/수정본 검증 없이 실제 사례라고 부를 수 없다. |
| 기존 자산 불변 + 통합 평가 3건부터 검수 | 이번 구현의 선택이다. 스키마·평가 관측의 결함을 드러내는 합성 기반이며 실제 분포나 성능 증거는 아니다. |

대표 단위는 **전체 문서군 + 요청 + 역할/사용 맥락 + 조회/편집 권한**이다. 제거·이동·추가·통합·윤문은 필요한 경우 선택하는 수단이다. 모든 액션을 강제하지 않는다. T1~T9는 새 입력·ID·주유형 분류에서 제거하고, 기존 회귀 자산의 태그와 오류 분석에만 재사용한다. 신규 태그 역시 분모가 아닌 관찰용이다.

역할·독자 정보 제공은 정당한 사용자 맥락이다. 입력은 어느 문장에 어떤 동작을 하라는 정답을 제공하지 않는다. 사용자가 실제로 지정한 보존/편집 제약은 지우지 않는다. 일반 허용 권한과 정답 동작은 다르다. 정보의 현재 과업 관련성이 낮아도 문서 전체에는 필요할 수 있고, 보존 의무는 다른 문서로 옮길 권한을 자동 부여하지 않는다.

IR-001/002는 명확한 사용자 맥락 아래 분석과 재구성을 수행한다. IR-003은 형식만 허용된 상태에서 의미 판단과 실행을 나누며, 전체 작업 중 일부만 보류할 수 있다. 출제 오류로 필수 명세가 빠진 사례와 의도된 공백을 혼동하지 않는다. 여기서는 세 번째의 회의 대상·내용 권한 공백만 의도된 평가 조건이다.

## D와 Q를 분리하되 단일 상태로 압축하지 않는다

기존 D/Q 분리는 유지한다. 다만 액션별 `required_effects` 집합을 맞추는 대신 근거로 뒷받침되는 판단 기준과 **전체 문서의 불변 조건**을 둔다. 명시 제약은 입력 포인터로 연결하며 추론한 요구와 별도 필드다. 확인 질문은 별도이고 새 사실을 추가하는 근거가 아니다.

D는 편집 전에 외부로 기록된 짧은 판단/근거인 `native_trace` 또는 `declared_plan`에서만 관측한다. 비공개 사고과정을 요구하지 않는다. 관측 없으면 `unobserved`; 출력이 좋아도 D를 역산하지 않는다. 자연 실행 Q와 공통 사전 계획을 요구하는 B0-D/B1-D/B2-D 실험을 분리한다. 사전 고정은 평가 운영자의 입력/아티팩트 해시 기록으로 관리하며 스키마의 boolean만으로 진위를 증명할 수 없다.

Q는 편집 가능한 모든 문서의 **전체 후보 또는 무수정 전체 원문**에서 과업·역할·정보·구조·표현을 본다. 읽기 전용 문서는 원문 스냅샷으로 결합해 대조한다. 불완전 출력은 Q `not_evaluated_incomplete`, 실행 실패는 별도이며 정당한 보류 성공으로 세지 않는다. IR-003은 공개판 완성도를 평정할 수 없지만 원문 보존·권한 준수·확인 질문은 평가 가능하다. 전부 `unresolved`로 뭉개지 않는다.

## 채점 운영안 — 아직 모델 실험 없음

| 관측 | 기록 방법 |
|---|---|
| D 기준 충족 | 각 D ID를 supported/violated/unobserved/review_needed로 기록하고 정확 근거와 사유를 붙인다. 주어진 액션을 맞힌 수로 세지 않는다. |
| 근거 품질 | 인용 정확성은 기계 검사, 판단 지지는 사람 검수. 지지된 주장 수/근거를 요구하는 제출 주장 수; 분모 0은 N/A다. |
| 보류 적절성 | 범위별 정당한 보류, 근거 없는 강행, 과잉 보류를 따로 기록한다. IR-001/002에서 이미 충분한 조건을 다시 묻거나 전부 보류하면 적절한 보류가 아니다. |
| Q 독자 과업 | 각 Q ID를 충족/위반/판단 불가로 기록한다. 전체성·정당한 보존·실제 사용 가능성의 증거를 함께 남긴다. |
| Q 품질 축 | 정보 보존, 목적 적합성, 완결성, 문서 배치/구조, 표현을 각각 0–3점. 0=필수 과업 불가/중대 오류, 1=주요 결함 잔존, 2=필수 과업 가능하나 개선 여지, 3=필수 과업과 문서 역할을 명확히 충족. 사례의 Q 조건을 평정 앵커로 쓴다. |
| 금지 결과·퇴행 | F ID 발생과 기존 고유 정보 손실, 새 허구, 원문/목적지 충돌, 링크 문제를 별도 기록한다. 좋은 문체 점수로 상쇄하지 않는다. |
| 집계 | D/Q 합산 평균 금지. 완료/실패/미평가 건수, 가족별 결과, 이견을 공개한다. 3건으로 성공률·일반 성능을 주장하지 않는다. |

정답 문자열이나 한 수정본과의 유사도는 채점 기준이 아니다. 각 대안 묶음은 모든 Q 조건과 금지 조건을 함께 만족해야 한다. 대안 A/B의 유리한 조각만 가져와 필수 조건을 누락하면 안 된다. 목록 밖 타당한 결과는 정답 재심 후 버전으로 기록하며 이전 결과를 보존한다. `reference_outputs`는 예시이지 모델 실행 기록이 아니다.

## 재사용 범위와 범위 밖

재사용: UTF-8 SHA-256, Unicode codepoint [start,end) 정확 인용, 입력/답안 분리, 사전 판단 관측, 전체 후보 요구, 복수 대안, 보류/실패 분리, 읽기 전용 검증, 사람 판단/포함 승인 분리. 이 구현은 PR #34 미병합 도구를 import하지 않고 작은 검증 패턴을 평가 전용으로 구현한다. 기존 전체 회귀 실행 도구와 활성 v3 검증기는 그대로 사용한다.

직접 호환되지 않음: case_id·단일 주유형·필수 액션/효과·문서 역할 3분류·단일 D 적용 상태. 새 스키마는 PR #34 검증기나 Core CLI에 그대로 넣을 수 없다. 추후 필요하면 명시/추론 계약·문서 권한을 Core 입력으로 매핑하는 별도 어댑터를 검토한다. 정답 의무를 Core 입력으로 주입하는 어댑터는 금지한다. Core의 추론·재구성·파일 적용 기능이나 게이트는 이번에 바꾸지 않는다.

## 남은 쟁점

합성은 문제 발견이 너무 쉬울 수 있고 작성자와 답안 작성자가 같다. 한국어 문서군도 긴 실제 문서·불완전 목적지·검색 선택의 분포를 대표하지 않는다. 현재는 관련 자료 전체를 제공하므로 검색 시스템의 recall을 평가하지 않는다. 대안 묶음과 Q 강제 조건의 과도함, D 사전 제출의 행동 변화, 부분 보류의 점수 해석, 서식 변경의 범위는 사람 캘리브레이션이 필요하다. 독립 사람 검수·모델 비교·실제 원문 출처 확보는 미실시다.
