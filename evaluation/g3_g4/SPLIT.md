# 개발용과 독립 홀드아웃 분리 계획

이번 신규 12건은 모두 개발용이다. 개발 에이전트가 원문과 AI 잠정 답안을 읽고 작성했으므로 감춰진 홀드아웃으로 사용할 수 없다. 홀드아웃 원문·정답은 수집하거나 이 저장소에 넣지 않았다. [split-plan.json](split-plan.json)은 노출된 개발 계열 제외 목록과 향후 관리 조건만 담는다.

| 단계 | 책임·산출물·통과 조건 |
| --- | --- |
| 개발용 후보 검수 | 사용자가 신규 계약·문맥·분류를 검토. AI 라벨과 사람 판단을 분리하고, 최종 확정 전에는 개발용 골드 적격을 부여하지 않음. 네 계열·네 원문의 상관성을 보고 |
| 홀드아웃 관리자 지정 | 사용자 또는 지정된 별도 수집 담당자가 개발 에이전트와 접근이 분리된 보관 위치를 관리. 아직 담당자·보관소는 지정되지 않았으므로 수집 완료로 보고하지 않음 |
| 신규 계열 선별 | 기존 6계열과 이번 4계열을 제외하고 다른 공개 저장소/원문 계열을 확보. upstream/fork/mirror/번역/인용 파생을 같은 계열로 묶고 전체 원문 해시·실질 중복을 대조. 주제가 같다는 이유만으로 같은 계열로 묶지는 않되 파생 관계를 확인 |
| 원문·라이선스 고정 | 관리자만 원문·라이선스·저작권 고지·commit/blob·SHA-256·수집 시각·선정/제외 근거를 보관. 공개 PR에는 원문 URL·본문·정답을 불필요하게 게시하지 않음 |
| 사람 정답 사전 고정 | 검증기 예측 열람 전에 입력·계약·사람 정답·검수 방식·한계·파일 해시를 고정. 단일 사용자 방식이면 그 사실을 명시. 새 AI 반례 검토도 검증기 평가 출력과 구별하고 정답 잠금 전에 완료 |
| 평가 요청 | 데이터 관리자가 잠긴 세트에서 실행하고 개발자에게 필요한 집계·가림 처리된 문제 유형만 전달. 검수자와 개발자 접근·실행 버전·모델/검증기 설정·예측·비용 기록 |
| 노출·튜닝 후 처리 | 오류/원문/정답을 열람해 프롬프트·코드·라벨 정책을 튜닝한 경우 해당 사례와 관련 계열은 개발용으로 이관. 이전 독립 성적은 고정 버전의 과거 결과로만 남기고 새 모델에 대한 독립 홀드아웃이라고 재사용하지 않음 |

향후 목표는 최소 4개 새 계열의 후보 12건과 정상/위반/보류 4/4/4다. 이는 계획상의 후보 배분이며 사람 판정을 강제로 맞추는 정답 할당량이 아니다. 실제 사람 판단과 자료 충분성에 따라 라벨 분포를 그대로 보고한다. 홀드아웃 표본 수·독립 계열 수·검수 수준·미해결률·오탐/누락과 불확실성을 함께 공개한다.

현재 도구는 이번 공개 개발 자료만 검사한다. 별도 보관소의 접근 통제·정답 사전 잠금·사람 신원 또는 아직 수집하지 않은 자료의 독립성까지 구현/검증했다고 주장하지 않는다. 독립 홀드아웃 수집은 후속 별도 작업이다.
