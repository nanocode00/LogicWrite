# Core 파이프라인 검증 실행 계획

사용자가 제공한 B/C/D 범위를 실행 기준으로 삼았다. 기준 main은 PR #21 병합 커밋 `29dd271c5e367044af765cc0ff9e81db52de7160`; Golden Set 트랙과 독립인 `core/pipeline-evaluation-next` 워크트리다.

- [x] 코드 변경 전 Core 340건과 실제 sample pipeline 결과를 기록한다. 원래 main 전체 테스트도 별도 프로세스로 보존한다.
- [x] 지정한 10개 모듈의 호출 경로와 후보 생성/승인 경계를 확인한다.
- [x] SP-001~012 입력만 읽는 진단과, 저장된 결과를 확정 정답에 대조하는 단계를 분리한다. SP 계약을 Core 계약으로 자동 등치하지 않는다.
- [x] 의미 위반, 입력 부족, 문서 이동, 수정 루프 종료와 하위 재검증을 통제된 native 사례로 실행한다.
- [x] 명시적으로 부분인 목적지를 조직화 모듈이 이동 가능한 문맥으로 간주하는 결함을 실패 테스트로 재현하고, 해당 조건만 수정한다.
- [x] 수정 전후 같은 평가 도구를 각각 main/Core 수정본에 실행하고 기존 회귀를 검사한다.
- [x] 근거 위치, 재현 명령, 오류 유형과 미지원 범위를 보고한다. 실제 사람 승인/정책 발급을 만들지 않는다.

대규모 리팩터링, 승인 정책 변경, G3 데이터 변경, G4 승격과 PR 병합은 실행 범위에 없다. 정답 대조는 평가 후의 읽기 전용 단계이며, Core 호출/모델 프롬프트에는 정답을 전달하지 않는다.
