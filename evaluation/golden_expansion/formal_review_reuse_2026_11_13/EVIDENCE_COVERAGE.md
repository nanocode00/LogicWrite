## 자동 채우면 안 되는 항목

| 항목 | 기존 기록으로 알 수 있는 값 | 보수적 처리 |
| --- | --- | --- |
| `reviewed_at`·최초 검토 시 AI 노출 여부 | 최초 검토의 실제 시각/노출 여부를 확정할 자료 없음 | 스키마상 `null` 허용. 지어내지 않음 |
| 사용자 리뷰어 식별자 | 단일 사용자였음 | 안전한 로컬 별칭은 가능하나 확인된 외부 인증 신원으로 주장하지 않음 |
| `initial.form.evidence` | 실제 최초 이유 있음, AI가 확보한 인용 후보 있음 | 증거 배열 비어 있어도 허용. AI 인용을 최초 사용자 인용으로 소급 귀속하지 않음 |
| VIOLATION의 `findings`, UNRESOLVED의 `missing_information` | 최초 이유는 사용자 원문으로 존재 | 원문 재사용 후보를 구분. 스키마 세부 구조·의미에 맞게 변환 가능한 범위만 변환 |
| 최종 `evidence` | Codex가 뽑은 인용 34개 | 최소 1개 정식 제출 필요. 사용자 직접 제출이나 명시 승인으로 주장하지 않음 |
| `counterreview.challenges`, `final.responses` | 가장 강한 반론 및 그 타당성에 대한 사례 단위 사용자 '동의' | 사례 단위 '동의'와 세부 `challenge_id`별 `accept/reject/defer`는 동일하지 않음. 자동 매핑 금지 |
| `confidence_limitations` | 단일 사용자+AI 검토의 방법론적 한계는 식별 가능 | 사용자의 최종 확인 사실은 미기록. AI 확인으로 승격 금지 |
| GC-003/006/009/012 최종 `unresolved_issues` | 사용자 최초 이유는 보존됨 | 최종 필드에 새 사용자 입력이 있었다고 소급 기재하지 않음 |
| 정식 hash-linked `user_initial → ai_counterreview → user_final` | 실제 검토는 존재하지만 정식 양식의 이벤트 체인은 부재 | 원본에 출처 링크를 추가하는 정규화 이력과 **정식 순서의 신규 이벤트**를 혼동하지 않음 |

## 이번 PR이 수행하는 것과 하지 않는 것

이번 작업은 `transcription_adapter.py`를 통해 기존 기록을 재판정 없이 읽고 `transcription.json`에 원본 SHA/JSON pointer로 연결한다. `format-mapping.json`은 서식 대응 지도이며, `suggestions.json`은 **확인 전** 증거 제안이다. 이 모든 산출물은 검토 보조자료이며 기존 `review.py`의 정식 심사 통과 결과가 아니다.

따라서 현재 기준 **포함 승인 17건, 적격 0건, 신규 활성화 0건**, 기존 v2의 12건을 유지한다. 새 v3 생성·기존 정책 완화·의미 재판정·과거 사용자 기록 수정·Core 승인/배포는 수행하지 않는다.

후속 검토는 이미 확정한 라벨을 다시 묻는 것이 아니라 **실제로 없는 필수 증빙이 무엇인지**를 확인하고, 필요할 경우 사용자에게 인용·challenge별 응답·한계를 제출받는 과정이어야 한다. 이를 신규 또는 후속 확인으로만 기록하고 과거 시각의 실제 이벤트였다고 주장하지 않는다.
