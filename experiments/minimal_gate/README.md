# 최소 검증 게이트 실험

상태: **합성 입력으로 실행하는 제한된 프로토타입**. M0 완료·M1 완료·공통 스키마 채택·골드 고정·문서 전달 승인을 뜻하지 않는다. 실험을 정식 엔진으로 채택하는 결정은 별도다.

## 목적과 설계

[공통 데이터 모델](../../docs/data-model-and-interfaces.md)의 계약·출처·보호 요소·필수 검사 완전성 원칙 중 일부를 실제 코드로 시험한다. Python 3 표준 라이브러리만 사용하며 외부 API·LLM·검색·문서 수정은 호출하지 않는다.

- 입력은 한 문서의 계약 요약, 변경 전/후 전체 텍스트 스냅샷, 수작업으로 지정한 보호 문자값의 전후 범위다.
- 검사는 계약 → 스냅샷 무결성 → 범위 참조 → 보호 문자값 일치 순으로 실행한다. 선행 검사를 통과하지 못하면 후속 검사는 미실행 사유를 남긴다.
- 검사 계획은 코드의 고정 정책으로 만든다. 입력 파일로 필수 검사를 줄이거나 모델이 만든 성공 결과를 제출할 수 없다.
- 각 필수 검사를 `{check_id, check_version}`로 계획에 고정하고 결과 한 행씩 대조한다. 내부 대조 함수는 결과 누락·중복·예상 밖 결과와 검사 버전 누락·불일치를 확인한다.
- 의미 검토는 구현하지 않았다. 고정된 `SEMANTIC_REVIEW` 행에 사람 판단 대기인 `not_run`을 기록하므로 **정상 입력도 최종 REVIEW**다. 사람이 이 실험에 PASS를 입력하는 인터페이스는 없다.

이는 세 편집 모듈의 대체 구현이 아니라 공통 검증 기반의 실험이다. 정보 추출·보존/배치 판단·문장 재작성·자동 수정 루프는 아직 수행하지 않는다.

## 실행

저장소 루트에서 실행한다.

```bash
python3 experiments/minimal_gate/gate.py experiments/minimal_gate/intact.json
python3 -m unittest discover -s experiments/minimal_gate -p 'test_*.py'
```

첫 명령은 JSON 보고서를 표준 출력으로 반환한다. 입력과 원문 파일에 쓰지 않는다. 출력 JSON은 ASCII escape를 사용해 특수 유니코드 식별자도 안전하게 직렬화한다. 프로세스 종료 코드 0은 보고서를 출력했다는 뜻이며 문서 통과를 의미하지 않는다. 판정은 보고서 필드를 읽는다. Python 3.12에서 확인했다.

## 실험용 입력

`intact.json`은 새로 만든 합성 자료이며 기존 평가 fixture·RW-001 입력·재검토 장부를 이 형식으로 변환하거나 골드로 사용하지 않는다. 공통 모델의 정식 WritingContract/DocumentSnapshot/ValidationPlan 직렬화가 아니다.

| 항목 | 지원 범위 |
| --- | --- |
| `contract` | 비어 있지 않은 `audience`, `purpose`, `document_type`과 한 개의 `output_scopes` 항목. 범위는 `{scope_id, document_id}`로 선언한다. |
| `source`, `candidate` | `{id, document_id, content, sha256}`. 같은 논리 문서의 서로 다른 스냅샷 ID다. `content`의 정확한 UTF-8 바이트로 SHA-256을 계산하며 줄바꿈·유니코드를 정규화하지 않는다. |
| `protected_literals` | `{id, scope_id, source_span, output_span}` 목록. 두 범위는 각각 `{snapshot_id, start, end}`이며 0부터 시작하는 유니코드 코드 포인트 반개구간이다. 값 자체는 원문 범위에서 읽는다. |

미확인 목적지 역할·여러 문서·문서 그룹·의미 보존형 요구사항·추가 필드는 이 프로필에서 지원하지 않으며 `UNSUPPORTED_PROFILE`/REVIEW로 남긴다. 실제로 선언된 미확인 목적지 역할을 잘못된 참조라고 단정하지 않는다. 지원 프로필 내 누락 필드·중복 ID·미선언 범위·잘못된 오프셋은 FAIL이다.

해시 일치는 **제공된 텍스트의 무결성**만 확인한다. 원격 원문의 진실성이나 출처 권위는 확인하지 않는다. 보호 문자값은 지정한 위치에서만 비교하므로 문맥·귀속·전체 필수 정보의 완전성을 입증하지 못한다. 빈 보호 목록도 의미 검토 의무를 없애지 않는다. 이 제한 때문에 전체 문서 PASS를 제공하지 않는다.

## 보고와 판정

계획/보고 정책 버전(`minimal-gate-spike-v2`)과 검사별 구현 버전(현재 각각 `1`)을 구별한다. 결과 버전은 해당 검사 ID에 선언된 기대 버전과 정확히 같아야 한다. 계획의 기대 버전 누락·오류도 실패이며, 결과의 `check_version` 누락은 `CHECK_VERSION_MISSING`, 불일치는 `CHECK_VERSION_MISMATCH`로 기록한다.

보고서는 고정 검사 버전·검사 목록, 입력 digest, 검사별 상태·사유, 보호 문자값의 전후 값과 범위, 실행 상태를 포함한다. 입력 digest는 실험 전용으로 `json.dumps(ensure_ascii=True, sort_keys=True, separators=(',', ':'))`의 ASCII 바이트에 SHA-256을 적용한다. 원본 JSON 파일 바이트 digest와 구별하며, 공통 산출물 해시 정책을 채택한 것이 아니다.

| 관측 | 실험의 결과 |
| --- | --- |
| 지원 구조·문자값 검사가 통과 | 개별 검사는 passed, 의미 판단 대기 때문에 최종 REVIEW |
| 필수 필드 누락·참조/해시 오류·보호 문자값 변경·출력 범위 누락 | FAIL과 해당 검사 사유 |
| 지원하지 않는 입력 범위 | REVIEW와 UNSUPPORTED_PROFILE, 후속 미실행 사유 |
| 필수 결과 행 누락·검사 실행 오류·입력 파일 읽기 실패 | STOPPED. 이미 확인한 실패는 last_gate_state: FAIL로 보존 |
| 중복·예상 밖 결과·알 수 없는 결과 상태·검사 버전 누락/불일치 | 보고 무결성 실패. 필수 결과도 누락됐으면 STOPPED와 last_gate_state: FAIL |

내부 대조 함수의 PASS 테스트는 합성 결과 행으로 완전성 분기를 확인하는 단위 테스트다. 실제 CLI 실행이 의미 검토를 통과한 증거가 아니다. 모든 반환에서 `delivery_approved`는 false다.

## 확인 범위와 후속 결정

테스트는 수치 변경, 누락된 출력 대응, 잘못된/중복 범위, 오래된 스냅샷 참조, 잘못된 해시·오프셋, 한글·이모지 코드 포인트, 검사 결과 누락·중복·실행 오류·검사별 버전 일치/누락/불일치, 잘못된/중복 키 JSON·디코더 한도·특수 유니코드 출력, 재현성·입력 불변성을 확인한다. 성능·편집 품질·독립 사람 검수·실제 설치/운영 동작은 평가하지 않는다.

후속으로 실험을 채택할지 검토하고, 채택한다면 정식 계약·스키마·검증 정책과의 매핑 및 테스트/CI 구성을 별도로 설계한다. 기존 골드 준비와 홀드아웃 확보 작업은 이 실험으로 완료 처리하지 않는다.
