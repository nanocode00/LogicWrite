# G4 준비도 및 구현 계획

**판정 `BLOCKED`.** G1~G3의 오프라인 검증은 확인됐다. IR 자연어 요청에서 편집 작업을 제안하여 전체 후보를 생성하는 실행 경로와, 하위 모델 호출 전체의 비용을 통제하는 조건이 아직 없다. 모든 필수 P0 행이 `READY`가 된 뒤에만 G4 실행을 검토한다. `PARTIAL`은 일부 구현 또는 일부 검증, `NOT_VERIFIED`는 현행 증거가 없는 상태다. 점검 기준은 `a1cee29`다.

## A. 문서군 파이프라인

| 우선순위 | 항목 | 상태 | 근거와 수용 조건 |

| P0 | G3 독립 검증·부분 HITL | PARTIAL | [G3 최종 증거](g3-final-evidence-20261118/REPORT.md). 기계 판정과 보고서 무효화가 확인됐다. 실험에서 쓰는 독립 검토자 출처, 사람 권한 조회, 결과 결속을 검증하는 통합 시험이 필요하다. |
| P1 | 제한된 수정·재검증 | PARTIAL | [단일 문서 수정 루프](../full_document_control/repair_loop.py)에 횟수·시간 제한과 호스트 어댑터가 있다. 문서군 G2-C/G3에 연결된 수정 루프는 확인되지 않았다. 첫 실험은 재시도·자동 수정을 비활성화하고, 후속 시험에서 실패한 후보의 재사용과 무한 루프를 차단한다. |

G4의 기본 자연어 조건에 운영자가 정답성 작업 목록을 보충하면 입력 처치가 달라진다. 작업 제안기를 B2 경로에 연결하기 전에는 이 결과를 같은 조건의 실제 B2로 집계할 수 없다. 수동 계획을 쓰는 별도 개발 시험은 입력에 추가된 계획과 범위를 기록한다. 정당한 무수정 후보와 과잉 보류는 작업별 근거로 구별한다.

## 최소 구현 순서와 착수 수용 조건

1. **P0 입력·판정 계약 고정.** 동일 IR 입력과 권한, 생성 허용 필드, 결과 분류, 독립 검토 계획을 고정한다. 기존 기준과 사람 판단은 보존하고 모델 메시지의 누설 검사를 추가한다.
2. **P0 오프라인 문서군 수직 통합.** 가짜 호출로 자연어 작업 제안 → G2-B → G2-C → G3를 연결한다. 금지 작업·근거 위조·계획 누락·정당한 무수정·과잉 보류·의존 작업·전체 출력 누락·오래된 보고서를 검증한다. 개발 사례의 문구를 생성기 규칙에 넣지 않는다.
3. **P0 비용 제어와 기록 통합.** 단계별 예약, 누적 상한, 원장 결속을 가짜 provider로 검증한다. 예산 초과, 불명 비용, fallback, 응답 절단, 타임아웃, 중복 실행과 재시작을 시험한다.
4. **P0 오프라인 수용검사와 실행 승인.** 현재 기준에서 전체 회귀를 실행하고 독립 검토자·사람 권한 조회의 출처 결속을 검증한다. 허용 모델/provider, 예산, 차단 정책, 비교 범위, 독립 검토 담당자를 확인하고 별도 승인을 받는다. 모든 P0가 `READY`일 때만 실제 호출을 검토한다.
5. **P1/P2 후속.** 첫 파일럿의 제한을 기록한 뒤 제한적 수정·재검증을 별도 오프라인 회귀로 추가한다. 독립 문서와 반복 실험에는 별도 데이터·예산·승인을 사용한다.

이번 점검에서는 실행기 구현, 키 조회와 모델 호출, 점수 생성, 파일 적용을 수행하지 않았다.
