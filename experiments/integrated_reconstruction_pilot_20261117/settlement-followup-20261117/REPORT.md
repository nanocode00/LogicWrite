# 정산 검사 보완 및 남은 비교 조합 실행

2026-11-17. PR #36. 생성 프로토콜은 `integrated-reasoning-allowed-20261117-v1`로 유지하고
서버 사용량 지연 처리만 보완했다. 기존 결과는 수정하지 않는다.

**정산 문제는 해결됐다. 남은 요청 중 IR-001/B0와 B1을 실행했지만,
B1의 보고 출력 토큰이 요청 상한을 초과하여 추가 요청을 중단했다.**
기존 IR-003/B0는 재생성하지 않았다. 캠페인은 총 3/6 요청을 사용했고 나머지 3건은 미실행이다.

## 정산 검사 변경과 감사 해제

- 응답에서 확인된 cost를 즉시 로컬 원장에 더한다. 다음 요청은 서버 반영 여부와 무관하게
  max(로컬 비용, 서버 usage)+요청 추정 상한으로 심사한다. 서버 지연을 0원으로 처리하지 않는다.
- 서버 usage가 확인된 로컬 누적보다 작으면 `lagging_known_costs`로 기록한다. 알려진 비용은 계속 예산을 차지한다.
- 미확인 추가 사용량·서버 값 역행·한도 조회 실패·불명 비용/토큰·timeout·출력 절단은 계속 차단한다.
  자동 polling·생성 재시도·병렬 호출·모델/provider fallback은 없다.
- 사용자 재시도 승인으로 `settle` phase를 실행했다. 고정 commit 82a4980의 기존 IR-003/B0
  응답/기록, 전체 후보, 원장 비용 이력, 현재 서버 정산을 확인한 경우에만 이전 정산 차단을 해제한다.
  pending/timeout/다른 실패는 이 경로로 해제하지 못한다.
- 원장 $0.0043091064를 유지하고 기존 응답 상태만 `response_complete`로 감사 전환했다.
  이전 실패 이유와 원본 산출물은 그대로다. before/event/after는 `release/settlement-*.json`에 있다.
- 생성 메시지·모델·provider·temperature·reasoning·출력 상한은 바꾸지 않았다. 키 lifetime $0.25,
  실행기 누적 $0.20, 캠페인 최대 6회도 유지한다.

## 새 중단 원인: 총 출력 토큰 정책 불일치

실제 `request.json`에는 `max_tokens=12000`을 보냈다. B1 응답 usage는 completion_tokens=16025,
그중 reasoning_tokens=14280을 보고했고 finish_reason은 stop이었다. reasoning만으로도 12000을 초과한다.
이는 응답 문자열이 잘린 사례와 다르다. 최종 JSON은 전체 문서를 포함하지만 **요청한 총 출력 예산을
준수한 비교 결과는 아니다.** 응답 usage 금액은 정상적으로 원장에 반영한 뒤 차단했다.

이번 실제 금액은 보수적 비용 추정 상한 이내였고 입력 토큰도 추정 이내였다. 따라서
일반 `cost_or_token_bound_exceeded` 중 실제 위반은 **completion token 상한**이다.
계산과 근거는 `token-limit-check.json`에 있다. provider 내부 원인이나 매개변수 해석은 확정하지 않는다.
출력 상한 확대, reasoning 회계 제외, 다른 모델/provider 전환, B1 재호출을 하지 않았다.
원장은 blocked=true, pending=false로 유지된다. 남은 IR-002/B0·B1 및 IR-003/B1을 보내지 않았다.

## D/Q/F 비교 초안 — AI 의견과 자동 검사 분리

`automatic-summary.json`은 파일·본문·코드 블록·링크 등 기계 진단이다.
`assessment-draft.json`은 승인된 사례별 기준/해시에 묶인 AI 의미 의견이다.
인용은 JSON Pointer/정확 인용으로 기록하고 `assessment-evidence-check.json`에서 문자 일치만 검증했다.
문자 검사로 의미 평가나 사람 승인을 대체하지 않는다. 모든 사람 최종 판단은 null이다.

### IR-001 진단적 B0/B1 비교

B0/B1의 원문 user 메시지와 생성 설정은 정확히 같다. B1은 일반 IMPROVED 지침만 추가됐으며
정답·검수·진단 태그·이전 결과는 전송하지 않았다(`paired-request-check.json`).
다만 B1의 실제 출력 토큰 한도 위반 때문에 **완전히 통제된 유효 비교 쌍으로 집계하지 않는다.**
다음은 받은 내용에 한정한 진단이며 B1의 일반 성능 향상 주장이 아니다.

| 기준/관찰 | B0 | B1 |
| --- | --- | --- |
| D | 사전 관측 없음, unobserved | 사전 관측 없음, unobserved |

양쪽 모두 유지보수 절차를 README에 계속 남기고 반복/불필요 정보를 충분히 정리하지 못했다.
좋은 표현이나 완전한 JSON이 B0의 F1을 상쇄하지 않는다. Q 품질 축은 각 기준 판단과 별도로
0–3 AI 초안 점수로 기록했으며 D/Q 합산이나 성공률은 만들지 않는다.
B1의 토큰/비용/시간 차이도 설정 준수 차이가 있어 공정한 효율 개선 수치로 해석하지 않는다.

### IR-003 및 미실행 사례

기존 새 프로토콜 B0는 목록 변환 없이 빈 줄만 정리하고 구체적인 질문을 했다.
그 응답을 이번에 다시 생성하지 않았다. B1이 미실행이므로 **목록 변환/질문 부족이 B1에서 개선되는지 판단 불가**다.
IR-002의 운영/개발 간격·적용일·중단 조건·제한 관찰은 아직 모델 평가하지 못했다.
B2는 기존 통합 구현 범위의 미지원 경계를 유지한다.

재현한 명령(기존 경로 재사용 금지):

이것은 관측에 따른 후보이며 Core 변경 승인이나 구현 성과가 아니다.
실제 한국어 사례는 승인/변경 이력이 있는 운영 런북, README/정책 충돌 문서군, 권한 제한 회의 문서와
수정 불필요 사례를 독립 조직·저자 가족에서 우선 확보한다. 현재 자료 1개 합성 가족으로 일반 효과를 주장하지 않는다.
