# LogicWrite G3 독립 검증과 부분 HITL

PR #36의 2026-11-18 오프라인 결과다. 모델 호출은 0회이며 후보와 검증 기록은 REVIEW 상태다.

## G2-C와 G3의 경계

G2-C는 전체 후보 조립, 허용된 MOVE/PLACE 배치, 원장과 trace의 바이트·범위 일치를 확인한다. G3는 원본과 실제 전체 후보를 직접 읽어 문서의 누락·추가·권한·변경을 확인하고, 별도 의무 계약에서 요구하는 문서 노출 위치를 검사한다. G2-C layout/trace 검사기는 작업 범위 검증의 보조 증거다. 내장 구조 보고서와 생성기의 자체 검증은 독립 판정의 입력 증거로 사용하지 않는다. 원장·trace 오류가 문서별로 확인되면 해당 문서로 영향을 좁힌다. 위치를 확정할 수 없는 전역 오류는 관련 작업을 보류한다.

| 인터페이스 | 입력과 결과 |
| --- | --- |
| `verify_document_set(result, requirements, **inputs)` | 핀으로 고정한 G1 원본 계약, G2-A 분석, G2-B 계획 및 요청, 후보 생성 요청, 전체 후보 결과, 독립 요구사항을 받는다. 후보 결과 핀에는 후보 전체, 원장, trace, 자체 검증이 포함된다. 검사별 판정·이유·문서·작업과 원본/후보 SHA-256, 유니코드/UTF-8 범위, 인용을 반환한다. |
| `requirements` | `document-set-requirements-v1`의 `obligations`와 `format_policies`를 호스트가 별도로 고정한다. 의무는 검사 ID, 소스 범위, 대상 문서, 관련 작업, 결정 권한자와 쟁점을 명시한다. 소스 인용에 시점과 적용 범위를 명시할 수 있다. |
| `independent_review` | 선택적인 별도 검토 레코드다. 검토자 ID, 전체 입력 결속, 리뷰 핀, 원본과 대상별 인용을 요구한다. 기계 판정은 변경할 수 없으며 미실행·부분 결과·미확정은 독립 의미 검토 대상으로 남는다. 인증된 외부 검토자/핀을 공급하는 책임은 호스트에 있다. |
| `is_current_report`와 `bind_hitl_record` | 현재 입력으로 독립 검증을 다시 계산해 보고서의 일치를 확인한다. HITL 기록 결속은 별도로 고정한 보고서·질문·결정과, 호스트 조회가 확인한 사람·권한자·철회 여부를 확인한다. 결속만으로 보고서 최신성이나 새 권한이 생기지 않는다. |

권한 검사는 무수정 후보를 허용하고, 읽기 전용 문서의 출력 승격과 명확한 서식 전용 어휘 변경을 위반으로 기록한다. 읽기 전용 문서가 후보에 없을 때의 판정은 제출 범위에 관한 것이다. 실제 작업 공간의 쓰기 여부를 판정하려면 별도 증거가 필요하다. 같은 어휘를 유지한 공백·마크업 변환은 별도 정책이나 근거가 없으면 unresolved다. 공백 정책은 독립 검토 근거와 정확한 원본/후보 해시에 결속한다.

`exact_line`은 대상 문서에서 날짜·단위·조건·부정을 포함한 완전한 줄이 있는지 확인한다. 코드 펜스나 주석에서만 나타난 문구는 산문 노출 미확정으로 남긴다. 이 검사는 해당 줄의 의미, 독자의 검색 가능성, 가까운 문단에 있는 예외의 적용을 확정하지 않는다. `semantic`과 `policy_relation`은 별도 검토 대상으로 두며, 후자는 두 원본의 근거와 권위를 보존한다. 문자열 차이로 정책 충돌을 확정하거나 정책 우선순위를 정하지 않는다.

확인된 결함의 영향 범위와 의미 판단이 필요한 질문을 구분한다. 각 질문은 결정 권한자, 필요한 결정, 근거, 해당 결정 전에 보류할 작업과 식별된 보류의 영향을 받지 않은 작업을 기록한다. 계획의 읽기·쓰기 범위와 작업 의존성을 전파한다. `independent_task_ids`는 식별된 보류에 대한 독립성을 표시하며 일반 의미 검토는 계속 REVIEW다.

## 원본-후보 비교

| 입력 | G3 기계 판정 | 의미 검토와 작업 범위 |
| --- | --- | --- |
| IR-001 B0/B1 | 두 후보 모두 출력 문서 집합을 충족한다. B0의 usage 변경은 오프라인 KEEP 전용 비교 계획의 범위를 벗어난다. B1의 두 대상은 원문과 동일하다. | README의 기부 안내와 FUNDING의 금전 후원 거절을 함께 인용한다. 어느 정책이 적용되는지는 후원 정책 권한자에게 묻는다. B1에서 `retain-funding-statement`가 보류되고 `retain-output-description`은 유지된다. |
| IR-002 B0/B1 | ADR-07의 “대기 건수가 500건을 넘으면 신규 배치를 중단한다. 당직자가 확인하기 전에는 재개하지 않는다.”가 두 ops 후보에 없다. 후보는 당직 채널과 대시보드만 안내하고 재시도 절로 넘어간다. 설계나 ADR에 있는 정보는 ops 의무를 충족하지 않는다. | 운영 정책 권한자에게 교대자용 중단·재개 조건과 현행/과거 적용 범위를 묻는다. ADR의 현행 운영 60초·개발 30초, 11일까지의 운영 30초, 주간 보고의 혼합 기간을 각각 인용한다. |
| IR-003 B0/B1 | B0는 meeting 원문을 그대로 반환했다. B1은 “1건 실패다.”를 “1건 실패.”로 바꿔 형식 전용 어휘 검사에서 위반이다. | 회의 용도와 공개 범위 등 G2의 기존 HITL을 이어받는다. 실패 원인의 일반 의미 판정은 unresolved다. |
| 합성 G2-C MOVE / 부분 후보 | MOVE 후보의 실제 원문·후보 및 trace/원장 결속이 통과한다. 부분 후보에서 `place-label`은 구조 검증을 통과하고 `move-alarm`은 원문 조건을 유지한 채 보류된다. | 조건을 포함한 이동 범위 결정은 해당 작업에 한정된다. 일반 의미 검토는 unresolved다. |

동결 Qwen B0/B1 여섯 파일의 바이트 해시를 기존 매니페스트와 대조했다. 결과는 외부 후보 shadow로 집계했다. IR-002 B0의 중단 조건 기재 주장과 B1의 `completeness_verified` 및 중단 조건 접근성 주장, IR-003 B1의 `within_authority`에 독립 검사 결과를 연결했다. 비정형 자체 검증은 오프라인 어댑터에서 알려진 JSON 경로와 원시 주장을 기록해 대응시켰다. 자유 서술의 의미를 일반적으로 판정하거나 미등록 주장을 자동 변환하지 않는다.

## 재현과 후속 검증

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s experiments/full_document_control -p test_document_set_g3.py
PYTHONDONTWRITEBYTECODE=1 python3 experiments/integrated_reconstruction_pilot_20261117/g3_offline.py --output /tmp/logicwrite-g3-shadow-new
PYTHONDONTWRITEBYTECODE=1 python3 tools/evidence_validation/run.py --output /tmp/logicwrite-g3-evidence-new.json
```

회귀에는 독립 검증 인터페이스 부재, 관계없는 문서의 trace 변조, 빈 후보 검토, 코드·주석에 숨은 문장 및 마크업 변경의 Red/Green 재현이 포함된다. 기존 원본, 골드, 사람 판단, 후보와 예산 원장은 읽기 전용으로 사용했다.

G4 전에는 실제 독립 의미 검토자의 출처 결속과 사람 권한 조회를 통합하고, 새 사례에서 의역·조건 결합·출처 귀속·정책 충돌·대상 문서에서의 독자 노출을 검증해야 한다. 동결 IR 3건은 개발 증거다. G4의 실제 비교에는 별도 승인, 고정 실행 조건, 호출 예산과 격리된 평가가 필요하다.
