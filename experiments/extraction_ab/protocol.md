# RW-001 단일 단계·2단계 분석 비교 — 사전 실행 규약

작성일: 2026-11-09 Asia/Seoul. 모델 실행 전에 이 규약을 커밋한다. PR #8 병합 main `e188cde751da9adf84f223b6913a226dfd616537`의 프로토타입을 재사용한다. 공통 스키마·골드·전달 승인 기준을 변경하지 않는다.

## 질문과 비교 조건

RW-001의 대안 비교·설치 요구사항 혼합과 요구사항을 실제 설치 동작으로 확대할 가능성에 대해, 단일 단계(A)와 추출 후 목적 평가(B)가 어떤 다른 제안을 만드는지 탐색한다. B가 개선될 것이라고 가정하지 않는다.

- 원자료: 기존 `RW-001.input.json`의 정확한 바이트. 답안·기존 모델 응답·재검토 라벨·이 비교의 검토 기준을 모델에 제공하지 않는다.
- A: PR #8의 `build_prompt()`를 그대로 호출해 한 번에 정보 분리와 목적 기반 평가를 수행한다.
- B1: 같은 원문·주변 문맥·출처를 받되 실제 독자·목적·사용자 요구와 기존 과제 지시는 보류한다. 원문 주장·조건·수치·출처·관계만 제안한다. 추출의 기본 규칙과 문자 인용 형식은 기존 방식에 맞춘다.
- B2: 원래 입력 전체와 B1 원시 정보 목록을 받는다. 독자·목적에 따른 범위별 관련성·중요도·보존·노출 및 정합성을 평가한다. B1의 ID·주장·인용·요소·관계는 변경할 수 없다. 잘못된 분할을 발견하면 불확실성/질문에 남긴다. 최종 결합은 코드가 수행한다.
- A/B 전체에 사용 가능한 원자료와 계약은 같다. B1에서 계약을 보류하고 B2에서 고정 목록을 평가하는 구성 자체가 실험 변수다. 각 호출의 프롬프트·정보 노출 시점·모델 호출 수는 같지 않으므로 물리적인 단계 수 하나의 인과효과로 해석하지 않는다.

## 실행 조건

- Antigravity CLI에서 확인한 `gemini-4-argon-medium` 모델 별칭을 모든 호출에 명시한다. 이 별칭은 요청 식별자이며 실제 백엔드 리비전의 동일성을 입증하지 않는다. temperature/seed는 제공 인터페이스에서 고정하지 못한다.
- 두 반복만 수행한다. 순서는 1회차 A→B1→B2, 2회차 B1→B2→A로 정한다. 기존 PR #8 실행을 새 A로 재사용하지 않는다.
- 호출별 timeout 180초, 자동 재시도·출력 정리·결과를 본 후 프롬프트 수정은 하지 않는다. 실패/시간 초과/JSON 오류도 결과로 남긴다. B1이 유효하지 않으면 B2는 실행하지 않고 이유를 기록한다.
- 매 호출은 새 임시 폴더·새 세션에서 수행하고 프롬프트만 공급한다. OS 수준 파일 접근 차단이나 평가 오염 부재를 입증한 것으로 보고하지 않는다.
- 실행 전 manifest에 입력/규약/코드/CLI 바이너리 digest, 요청 모델, 순서, 시간 한도를 기록한다. 각 호출의 원시 stdout/stderr·프롬프트·종료 코드·시간을 로컬 `runs/`에 보존한다.

## 결과를 보기 전에 정한 검토 질문

1. 서로 다른 기능·주장 범위의 정보를 묶어 독립 판단이 어려워졌는가? 분할 수가 많거나 적다는 이유만으로 좋고 나쁨을 결정하지 않는다.
2. “앱이 요구한다”, “더 적합하다”, “기대 이점”, “나중에 가능하다”를 실제 설치 동작·검증된 효과·확정 계획으로 바꿨는가?
3. 이번 릴리스, non-blocking, signed/notarized, 미래 가능성 등의 조건과 주장·근거 관계를 추적할 수 있는가? 인용에 있다는 사실과 정규화된 주장/요소에 보존됐다는 판단을 구별한다.
4. 관련성·중요도·보존·노출 판단의 이유가 지정된 독자 과업 및 원문의 문맥상 기능에 맞는가? 주제 일치만으로 정당화하거나 유용성을 검증된 사실로 승격하지 않았는가?
5. B1의 잘못된 분할/생략이 B2에 고정되거나, 분할 후 조건/근거 관계가 사라지는 새 오류가 생기는가? 반복 간 결과가 달라지는가?

코드는 인용·문자값·참조·단계 간 불변성만 검사한다. 위 의미 질문은 Codex 모델이 원문 근거를 붙여 수작업으로 검토하고 독립 사람의 승인을 요청할 항목으로 남긴다. 자동 의미 검증·골드 채점·정확도/재현율·통계적 개선을 선언하지 않는다. 의미 미검증은 REVIEW와 delivery_approved:false를 유지한다. 구조 오류는 기존 FAIL/STOPPED 정책대로 보고한다.
